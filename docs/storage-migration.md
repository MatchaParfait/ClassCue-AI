# 保守的目录迁移

设置 → 存储与导入中修改目录后，先点击“检查并迁移”。界面显示文件数量、总容量、目标磁盘空间及迁移范围；点击“开始迁移”后在后台复制并进行 SHA-256 校验。全部文件校验通过后，切换配置和视频文件引用，再清理原文件。进度保存到现有任务表，刷新页面可继续查看。

视频和音频使用一个“视频与音频存储目录”入口。选择目标文件夹后，后端自动派生并创建 `videos`、`audio` 两个子目录，一次性迁移两类文件。已绑定后不能再单独修改子目录。旧安装的 `temporary_audio` 或分开配置的位置在用户确认迁移前保留，修改其他设置不会隐式搬迁；“恢复默认存储目录”也通过相同的预览与迁移流程，将二者归入默认父目录。

## 范围

| 内容 | 行为 |
| --- | --- |
| 临时音频与转写缓存 | 迁移当前配置目录内的文件 |
| 模型权重 | 迁移 `models/asr`，排除跨进程锁目录 |
| 环境下载缓存 | 迁移 `.runtime/cache` |
| 视频库 | 仅迁移当前库目录内已登记的视频；更新 `video_path`，保留视频 ID、原始来源信息、文件夹、字幕、考点、复习状态 |
| 独立 Python 环境 | 原位保留，避免破坏环境中的绝对路径；更换 ASR 资源目录后重启，在新位置按需准备环境 |
| 历史日志 | 原位保留，新日志目录重启后生效 |
| 数据库、配置与凭据 | 使用下方独立的“应用数据”入口，确认后迁移并立即重启 |
| 外部原始来源 | 不迁移 |

不会自动下载模型、重建环境、搜索和清理历史目录。迁移成功也不代表旧 ASR 根目录一定变空：旧环境、锁文件或未纳入迁移的内容会保留。

## 应用数据：确认后迁移并立即重启

“应用数据”将体积较小的数据库、设置与加密凭据统一放入一个用户选择的父目录：

```text
所选目录/
  library/project.db
  config/ai_providers.json
  config/asr_settings.json
  config/video_trigger_library.json
  config/ai_keys/*.dpapi
```

兼容的旧版加密密钥文件也包含在迁移范围中。仅复制明确登记的配置文件，不搬运整个历史 `data` 目录；凭据保持加密字节，不解密。视频、音频、模型、运行环境与日志沿用各自的目录。

选择目录和“检查迁移范围”均不执行迁移。检查后弹出确认窗口，明确提示“修改应用数据目录后，软件会自动立即重启”，展示目标子目录、文件数、容量与磁盘可用空间。默认焦点在“取消”，支持 Escape 取消；只有点击“迁移并立即重启”才执行。

确认后，后端阻止新写入并调用当前安装的一键启动器，停止经身份校验的服务，离线备份 SQLite 数据库，检查完整性和表内容指纹，复制校验配置，最后原子更新 `data/asr_storage.json` 中的定位信息并立即启动新实例。前端自动重连，刷新页面也会继续等待本次结果。启动器使用进程创建时间及实例身份，不停止无关服务。手动运行、未由启动器管理的后端不能执行自动重启迁移。

原数据库和配置保留为恢复备份；不覆盖内容不同的目标文件。提交定位信息之前失败时沿用原数据重启；提交之后中断时按已提交的新位置恢复。逻辑视频库身份和前端导航作用域保持不变，不产生新的工作区。程序目录保留很小的机器目录定位文件与迁移恢复记录。

此流程立即触发重启，不提供“安排下次启动迁移”的操作。正在运行或暂停的任务会阻止执行。若系统终止应用导致自动重连未完成，重新打开应用时会根据已持久化的迁移记录恢复；不会依赖前端页面保持打开。

## 失败与恢复

- 目标磁盘空间按卷汇总检查；复制仍需预留完整大小，不依赖原子移动或跨盘重命名。
- 新旧目录不得互相包含，不同类型的目录不得交叉或互换，不能覆盖数据库、配置与应用目录。
- 目录联接、符号链接及特殊文件不支持迁移，发现后停止。
- 不覆盖目标文件；同名同内容可复用，同名不同内容停止并恢复原设置。
- 开始时重新扫描并比较预览签名；内容变化后必须重新检查。
- 复制、校验或持久化失败时恢复原配置与数据库路径，保留原文件。只回收本轮创建且身份未变化的目标文件，不删除预先存在的目标文件。
- 成功切换后，原文件若被占用或发生变化则保留，并在迁移结果中显示具体位置。
- `data/storage_migration.json` 记录提交阶段。启动时持有数据库独占锁恢复：提交前中断恢复原配置和路径；提交后中断继续清理。提交前遗留的有效目标副本允许下次重试复用。
- 后台迁移占用现有单任务队列。运行或资源暂停的任务阻止迁移；迁移期间阻止其他写入。模型位置改变后，重启前阻止新的模型任务，避免继续使用旧进程固定的路径。

## API

- `POST /api/settings/directories/preview`：`media_storage_root`、`asr_storage_root`、`log_dir` 等设置字段，返回只读预览及 `plan_id`。`media_storage_root` 由后端派生为 `videos` 和 `audio`；旧的独立目录字段仅用于兼容尚未绑定的安装，不能拆分已绑定的目录。
- `POST /api/settings/directories/migrate`：相同设置加 `plan_id`，返回 `202 {job_id}`。
- `GET /api/jobs/{job_id}`：任务类型 `storage_migration`，`migration` 字段提供阶段、字节数、文件数及保留文件的说明。
- `GET /api/settings/directories`：`migration_job` 返回最近一次迁移，页面重载后可恢复进度。
- 兼容的 `PUT /api/settings/directories` 同步执行同一迁移逻辑，不再只改路径。只修改导入删除偏好时不搬文件。
- `POST /api/settings/application-data/preview`：`destination`、`library_id`，返回只读的应用数据迁移预览与 `plan_id`。
- `POST /api/settings/application-data/migrate`：上述字段加 `plan_id`，确认后立即启动迁移重启，返回 `202 {id, status: "restarting"}`。
- `GET /api/settings/directories` 的 `application_data.migration` 返回应用数据迁移结果；该流程不占用待搬迁数据库中的任务记录。

## 验证

`tests/test_storage_migration.py` 覆盖真实文件迁移、视频数据保留、同名冲突、目标复用、合计空间不足、校验失败、配置失败、嵌套目录、预览失效、清理失败、写入互斥和进程中断恢复。`StorageDirectoriesSection.test.tsx` 覆盖预览确认、草稿保留、失败提示、后台进度恢复与历史记录不覆盖新编辑。

`node tests/frontend_storage_migration.cjs` 启动独立临时 API，实际复制测试文件，验收冲突保留、进度、刷新恢复和 1440/1024/390px 布局。请求转发到测试实例，绝不修改当前用户库或调用 AI 服务。

`tests/test_application_data_migration.py` 覆盖应用数据的离线复制、身份与路径保留、冲突、锁、复制失败和提交后中断恢复；`ApplicationDataSection.test.tsx` 覆盖明确确认、取消、焦点和自动重连结果。`tests/test_webui_lifecycle.py` 使用独立安装与端口实际调用迁移接口，验证立即重启、数据生效和无关进程保留。

`node tests/frontend_application_data.cjs` 只读验收重启警告弹窗、键盘焦点、Escape／取消与 1440／1024／390px 布局，拦截所有迁移和设置写入，不移动当前用户数据。
