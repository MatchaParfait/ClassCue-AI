# 题目理解与字幕核验框架

## 本轮范围

已建立后端框架，并接入复习页的考点级宽弹层，打通：

```text
既有考点 + 视频截图 / 已选 PPT 图片 + 课堂字幕与课程
  -> 单次图文模型分析
  -> 原题事实、推导、待明确内容、逐项核验要求
  -> 精确知识点 / 课程类别搜索
  -> 候选字幕宽松定位 -> 候选截图及附近字幕复核
```

前端支持已有 PPT 手动选择、播放器当前画面截图、分析摘要及搜索结果；不再提供学习要求和题目文字输入框，主要通过题图理解题目。
后端保留文字与补充说明字段，兼容已保存材料和历史分析；本次界面精简不清空已有数据。
任意本地图片选择和分析结果直接编辑尚未接入。
不自动选图，不做 OCR，不联网下载图片，不修改原考点的考试置信度。
不要求 DSH、MCP 或模型自主调用工具，现有后端负责工作顺序。

## 前端工作区

复习页原有“查找 B 站讲解”入口打开同一个宽弹层，包含三个页签：

- **题目材料**：课程、原字幕依据、视频截图与已有 PPT 选择，不要求手工填写题目或学习要求；PPT 默认列出考点前后 20 秒内重叠的时间实例，可切换全部或已选范围。最多手选 4 张，不自动选中；缩略图标注展示区间与实际截图时刻，放大在当前面板内展示。
- **AI 理解**：单独执行分析，展示材料事实及来源、知识点与解法推断及依据、待明确内容、字幕核验要求和允许变化。历史选择仅用于查看，不改变后端采用的最新有效分析。
- **搜索与结果**：保留可编辑搜索词、精确与课程检索、目标要求、候选与字幕证据、账号登录和手动继续流程。

材料保存不调用 AI；分析前保存当前图片选择和课程。分析成功后仍需手动生成搜索方案，不自动访问 B 站。
修改材料立即禁用旧目标的搜索；保存后由后端按输入指纹判定历史过期。
分析与搜索进度在页签之外显示，切换页签或浏览历史不改变停止操作的任务对象。
关闭面板不会自动取消任务；未保存材料沿用原有离开保护。重新打开时恢复持久化材料和历史，不自动发起外部请求。

默认收起的运行详情显示分析 ID、模型、协议版本、输入快照、课堂字幕上下文及结构化分析；
搜索记录显示关联分析 ID 与核验目标。这里不提供直接编辑模型事实、指定旧分析重新搜索或自动对比多模型结果。
带图片的实际分析仍要求当前配置模型支持图像输入；模拟测试不证明真实模型的识题能力。

### 截取当前画面

在题目材料页点击“从视频截图”，临时隐藏弹层并解除背景锁定，仅在页面顶部显示截图工具条。
用户可操作原播放器、拖动进度条；课程、图片选择及面板滚动位置保留，不要求先保存草稿。
在工具条点击“截取当前画面”，会暂停原播放器，使用其当前已加载的原始分辨率画面生成 PNG。
本地上传成功后自动回到题目材料；点击“返回题目材料”或按 Escape 可不截图返回。
上传期间阻止重复截图及提前返回；失败保留取景工具条和错误提示，允许重试或返回，不自动调用 AI。
视频未就绪、正在定位、无视频尺寸或画面超过像素限制时拒绝截图，不用旧帧充当当前帧。
记录播放器截图时的 `currentTime`（毫秒），不假称它是解码器逐帧 PTS。
图片仅上传到本机后端，不触发模型或 B 站请求。上传成功后加入当前选图草稿；保存材料或点击分析后保存选择。
已上传但未选入的图片仍在当前考点的截图列表内，可重新选择或删除。

截图与 PPT 共用 4 张题图上限；单考点最多保留 20 张截图，每张最多 6 MB、1600 万像素。
截图保存在视频库旁的 `question-captures/`，数据库只保存所属考点、视频、播放器时间、尺寸、格式和内容哈希。
应用数据迁移后按现有 `library_scope` 保留原截图目录，不因数据库位置改变而丢失引用。
截图引用使用 `capture:<id>`，分析前校验所属考点、实际图片和哈希，发送实际图片字节。
删除截图会同时移除已保存材料中的引用，并使相关分析过期。视频删除会清理对应截图文件；
考点被重新分析替换等级联删除通过事务队列登记清理，在下一次题目请求或服务启动时清理文件。
历史分析保留文字快照，已删除截图不可再读取。

## 分析协议

模型结果的 `kind` 为 `exercise`、`topic` 或 `unclear`：

- `facts`：材料明确提供的条件、任务或主题，必须引用实际传入的来源编号。
- `knowledge_points`、`methods`：模型推导，必须引用事实编号；不能当作原题直接证据。
- `criteria`：逐项核验要求、重要性、深度及所需字幕证据，引用事实或推导编号。描述可迁移的知识点、题型与解题能力，不把原题实例字母、数值、逐轮中间结果和最终答案作为候选的硬性要求。
- `allowed_variations`：类似题允许变化的条件；不强制另一视频使用模型建议的唯一解法。
- `unknowns`：看不清、缺失或矛盾内容。
- `keywords`：简短的标准知识点名、题型名、方法名或别称，供后续搜索规划及长字幕选段使用，不填写完整题干和实例答案。

没有完整题目时可识别为考点并寻找该考点的例题；不能伪造原题。
无法建立目标时返回 `unclear`，不生成搜索目标，搜索接口要求先补充材料。
来源编号有效只能证明材料可回查，不能自动证明模型的理解正确。

转换后的目标保留原题条件、任务、建议方法、允许变化与不确定信息。
搜索模型负责生成搜索词，不能自行降低该目标的例题深度。
候选核验要求视频自身提供条件、方法与步骤，原题事实不能替代候选证据。
默认图文模式允许题目条件由候选画面提供，不要求字幕逐项口述。
结果状态仍为覆盖、部分相关、不相关和证据不足，并独立展示同知识点、类似题型、
解题讲解三项判断。关闭截图复核时仍使用纯字幕流程。

### 类似题与原题的边界

当前默认寻找同知识点、同题型的类似讲解，不要求原题复现。
原题条件保留在事实和 `comparison` 中用于理解题型，但不能要求候选具有相同的属性名称、
系数、对象名、完整条件列表、中间步骤或最终答案。关键结构、适用条件和讲解深度仍需保留。
例如属性闭包计算应核验函数依赖的使用、集合扩充过程与停止判断，
不能因为课堂某题闭包恰好等于属性全集，就要求所有候选例题也得到属性全集。

搜索规划通常采用 2 至 5 个简短术语，至少有一条“知识点或题型 + 例题”；
其余可使用别称或通用方法名，不将完整核验要求直接用作搜索词。
课程兜底搜索使用课程或较宽章节名称，补搜改写沿用相同规则。
例如可搜索“数据库 属性闭包 例题”，不拼接原题每条函数依赖和闭包答案。
这不是机械删掉所有数字或符号：具有区分作用的标准术语和题型结构仍需保留。

字幕核验的 `same_example` 表示候选视频内部的条件、方法与步骤属于同一道例题，
并不是说候选必须与课堂原题完全相同。不能把候选中的不同例题拼成一份完整证明。

当前提示词版本为 `question-analysis-v2`、`bilibili-harness-v4`、
`bilibili-visual-v1`；纯字幕路径继续使用 `bilibili-evidence-v3`。
旧分析和搜索记录保留供回看，但不再作为新任务依据，用户需要重新分析并生成搜索方案；
不会后台自动改写原记录或调用模型。定向测试使用假模型检查提示词约束、目标传递、
版本失效和引用核验，不代表已经验证真实模型生成搜索词的质量。

### 运行额度与停止原因

运行记录的 `budget`、`limits` 分别保存累计用量和本任务上限，
覆盖 B 站接口请求、AI 请求、视频详情尝试、字幕读取尝试、进入字幕核验的单元、
累计运行秒数和文本额度估算。`phase_limits.exact` 保存精准阶段的上限快照，
这些上限是总额度内的阶段限制，不是额外额度。

额度停止时保存 `budget_stop`，包含触发项目 `resource`、适用范围 `scope`、
当时阶段 `phase`、已用 `used`、上限 `limit`、下一步需求 `requested`，
以及已计入该需求的综合核验预留 `reserve`。时间到达上限与下一步预计超限都能明确追溯；
停止事件和阶段转移事件也保存同一份详情，刷新或重新打开后仍可查看。
若底层读取未提供具体项目，或旧记录从未保存此信息，页面明确显示未知，不根据计数猜测。

搜索与结果页显示原七项用量，以及新版记录中的视觉单元、取帧尝试、
浏览器请求及字节数的“已用、总上限、剩余”、精准阶段上限及停止原因，
不再仅因一个维度触限就称全部预算用完。文本额度是内部保守估算，不等于实际 Token 或费用。
本次不提高默认上限；已有的手动追加预算仍最多一次，继续时保留累计消耗和历史触发详情，
清除当前停止提示，不自动重启外部请求。阶段转移仅在检索过程中发生，方案生成阶段触限则报告失败。

### 字幕分块与引用兜底

B 站字幕核验复用课堂 ASR 考点分析的时间分块函数：每块最多约 300 秒，
相邻块保留约 30 秒上下文，并保留每块 12,000 字符的独立上限。
超长的单条字幕保持完整，不伪造句号或时间；超过单分 P 总选取上限时仍明确记录部分覆盖。
稀疏选取的字幕范围分别分块，不把未发送的中间字幕视为已读取。

分块提取优先返回真实字幕的起止编号，后端按原始顺序展开为连续证据；
不要求字幕编号数值连续，也不让模型生成时间戳。离散证据仍支持 `segment_ids`，
新范围协议兼容旧的离散引用。起止编号越界、反向、跨越未发送字幕时拒绝采纳。
同一要求可以有多条证据，跨块的条件、方法和步骤仍需在综合核验时确认属于同一道例题。

成功块单独保存；分块策略变化会使尚未完成的核验状态重新校验，不自动覆盖已完成历史。
综合判断先通过严格的要求、证据归属、例题连续性校验，失败时仅允许一次携带校验原因
及原返回的纠正请求，并继续计入任务额度、接受取消。再次失败或额度不足则保留分块证据，
不保存成功推荐，不循环重做整段视频。格式修复与语义引用纠正分别有固定的重试上限。

## API

| 请求 | 用途 |
| --- | --- |
| `GET /api/markers/{marker_id}/question` | 返回材料和最近 20 次分析，不调用模型 |
| `PUT /api/markers/{marker_id}/question` | 保存 `text` 和 `slide_ids`，不调用模型 |
| `POST /api/markers/{marker_id}/question/analyze` | 使用当前 AI 连接发起一次分析，返回分析 ID 与任务 ID |

保存示例：

```json
{"text":"请寻找演示候选键求解过程的例题。","slide_ids":[12]}
```

PPT 编号必须属于该考点的视频。最多手动选择 4 张图片，单张最多 6 MB、1600 万像素，
支持静态 JPEG、PNG、WebP；发送前验证实际格式、可解码性及内容哈希。
图片以图文消息发送到用户当前配置的模型；本地路径不发送，图片字节不写入数据库或日志。
`capture_ids` 可选，保存已上传的本考点截图编号，与 `slide_ids` 合计最多 4 张。

- `POST /api/markers/{marker_id}/question/captures?captured_at_ms=...`：二进制图片请求体，`Content-Type` 为 JPEG、PNG 或 WebP。
- `GET /api/markers/{marker_id}/question/captures/{capture_id}`：读取该考点的截图，不返回本地路径。
- `DELETE /api/markers/{marker_id}/question/captures/{capture_id}`：删除本地截图与已保存引用。
- 题目状态接口新增 `captures`，页面可刷新恢复已上传截图。

任务类型为 `question_analysis`，进度与取消复用 `/api/jobs`。
分析与搜索、ASR、PPT 任务共用现有互斥控制。
关闭或重启不自动恢复模型请求；收到完整且有效的结果时先保存，随后处理取消。
失败只保留可理解的错误说明，不存放供应商原始错误或无效响应。

无题目材料且无分析记录的旧考点继续沿用原有文字搜索。
存在题目材料时先分析，再调用现有 B 站规划接口；分析后可直接复用原搜索与核验接口。

## 保存与失效

SQLite 增加 `question_materials` 和 `question_analyses`。
快照包含当前考点、课堂字幕指纹、补充信息、题目文字和所选 PPT 的时间及哈希。
对应材料变化使旧分析和绑定它的 B 站搜索结果过期；不会按标题迁移。
图片发送前额外校验磁盘内容哈希；图片缺失、变化或路径越界会阻止模型请求。
读取历史时依据数据库元数据判断过期，不逐次扫描图片文件。
删除考点或视频时级联清理对应分析；PPT 图片继续由现有模块管理。
记录保存模型配置和协议版本，不保存 API Key 或 B 站凭据。
