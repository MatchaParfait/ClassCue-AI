## 文件导入

### 同时统一文件归属、来源处置与恢复入口

2026-11-09 · 关联源码：[统一入库](../classcue/video_library.py)、
[原生拖入](../classcue/desktop_video_drop.py)

浏览器上传只有文件字节，桌面移动需要原生路径。统一入口时要把来源处置集中处理，
副视角关联和批次回执必须先于来源删除。重复保护也应覆盖旧外部引用与库文件缺失，
保留原名称及本次来源。CLI 改为移动后，续跑要按持久来源归属找回托管文件，
不能只扫描原目录。原生拖入还需覆盖快速重绑与页面重载，使用真实 pywebview
事件对象检查注册及解绑，完全 Mock 会漏掉底层节点注册表的代次变化。

## 发行与更新

### 发行清单与更新路径分别校验

2026-11-08 · 关联源码：[发行路径校验](../classcue/release_security.py)、
[清单测试](../tests/test_release_manifest.py)

**问题：** 新增插件模块和 Skill 已加入发行清单，但更新器仍使用旧的精确允许路径，
导致本地功能正常、实际发行文件却被拒绝。若测试先要求文件已暂存，
未提交的开发工作区还会先报 Git 状态错误，遮住后面的路径规则问题。

**经验：** 发行清单负责选择文件，更新路径规则负责限制写入位置，两者需同步维护。
保留严格的暂存检查，同时独立遍历清单验证允许路径，使开发阶段也能发现遗漏；
新增文件只增加对应的精确路径，继续测试越界、保留目录和私人状态文件被拒绝。

## 焦点与快捷键

### 同时覆盖鼠标和键盘交替操作

2026-11-06 · 关联提交：`85270fc`

**问题：** 倍速菜单分别用鼠标、键盘操作都能正常工作，但鼠标打开菜单后，
直接用方向键选择、按 Enter 确认或按 Escape 关闭，焦点虽回到倍速按钮，
程序仍按鼠标操作处理；随后按空格会控制视频。

**经验：** 焦点位置和用户当前的操作方式需要一起考虑。菜单内发生明确的
键盘操作时，应及时切回键盘模式；下一次鼠标操作再恢复视频快捷键。
测试除了分别覆盖鼠标和键盘，还要覆盖两者交替使用，尤其不能都以按 Tab 开始，
否则会提前设置正确状态，掩盖缺陷。

## 标签与页面状态

### 标签身份与返回位置分别维护

2026-11-07 · 关联源码：[标签栏](../frontend/src/components/ReviewTabs.tsx)、
[资料阅读页](../frontend/src/pages/StudyMaterialsPage.tsx)

**问题：** 每份资料单独登记标签会挤占顶部空间；整体入口若只记固定地址，
又容易在切回时丢失当前课程和文件。关闭标签若先删除记录再确认离开，
用户选择继续编辑后，原页面虽还在，标签却已经消失。

**经验：** 学习资料标签使用固定身份，返回地址随前台页面更新，保留课程、文件和视图。
在页面入口登记，覆盖课程列表、空课程和视频例题；后台缓存页不主动加回标签。
文件仍在阅读器内切换，地址中的明确选择优先于最近阅读记忆。
关闭当前标签先处理未保存内容，确认后再删除标签和跳转；测试要覆盖同一课程内
切换不同文件，以及取消关闭后保留标签和草稿。

## 音视频同步

### 小幅漂移不要反复跳转音频

2026-11-07 · 关联源码：[播放器](../frontend/src/components/VideoPanel.tsx)

**问题：** 分开播放画面与音频时，每帧检查并在相差 0.12 秒后设置音频进度，
容易将暂时的解码延迟变成连续跳转；倍速播放更容易触发。

**经验：** 定时检查即可，小幅误差用有限的速度修正，大幅偏差才跳转，并设置
跳转间隔、等待正在进行的定位完成。误差换算成实际播放时间后再判断，避免
倍速放大校正频率；用户拖动进度、切换来源仍立即定位。测试检查跳转次数和
快慢两个修正方向，实际噪声是否消除仍需听感确认。
同步引起的轻微调速也会触发倍速事件；降噪应保留连续的音频缓冲，避免每次
追齐都清空处理状态。用户切换倍速档位或拖动进度时仍重置。
异步播放请求被暂停或换源中断，不等于播放故障。提示前确认仍需播放且尚未恢复，
恢复事件清除对应音频错误；失效来源的迟到回调和提示定时器应随来源退出。

## 有限预算的自动处理

### 先快速尝试，再有界兜底

2026-11-07 · 关联源码：[副视角对齐](../classcue/secondary_alignment_worker.py)

**问题：** 只限制识别条数，不能保证额度用在有效内容上。开场的静音和点名会让
大量短语音占满调用次数，而这些文字又达不到可靠匹配的长度。

**经验：** 先用低成本筛选和小预算覆盖多个有价值位置，证据不足再扩大搜索，
不要通过降低防误匹配门槛换取成功提示。阶段共享识别结果和总额度，各位置也设
局部额度；后续阶段不能把前一轮开销清零。分别限制识别音频、调用次数、扫描量
和实际运行时间，界面说明所用模型及停止原因，避免用户把“无匹配”误解为模型故障。
检查额度耗尽时，应区分“音频已经识别”和“输出已经检查”：剩余结果有界缓存，
供兜底继续处理，避免去重机制把有效证据一起封死。搜索前后方向也要轮流分配，
否则即使总额度充足，单侧搜索仍可能提前耗尽局部额度。

## 课堂片段与证据时间

### 讲解关联区间不能替代图片实际出现的时间

2026-11-07 · 关联源码：[片段快照](../classcue/codex_video_clip.py)

**问题：** PPT 的讲解区间、同页组范围和图片实际可见区间含义不同。
按同页组寻找精选图时，可能把稍后才出现的完整公式或答案发给当前较早片段。
同一图片又可能在多个时间出现，直接去重会丢失时间对应关系。

**经验：** 为限定时间的课堂提问选择图片时，应检查精选状态的实际可见区间，
不能用讲解区间或同页组范围代替；按内容去重时保留本范围内的时间实例。
字幕没有可靠的词级边界时保留相交的完整句子及原时间，明确可能跨越选定边界。
预览与发送之间重新核对内容身份，避免异步更新后发出与预览不同的材料。

**验证要点：** 使用同页组内晚出现的答案图、同图重复出现及跨边界字幕构造合成测试，
检查不会混入未来图片、去重后仍保留各次时间，预览之后修改材料会阻止发送。

### 预览有效性与材料身份分别判断

2026-11-07 · 关联源码：[片段快照](../classcue/codex_video_clip.py)、
[片段讲解](../frontend/src/components/CodexVideoClip.tsx)

**问题：** 重新提取相同 PPT 会更换数据库行 ID；直接用预览指纹或行 ID
判断讨论身份，会为完全相同的材料重复创建讨论。历史讨论与当前预览共用成功状态时，
打开一个旧讨论又会错误禁用当前片段的准备按钮。

**经验：** 预览指纹可以包含行 ID，用来阻止陈旧选择；讨论身份应使用稳定的视频身份、
范围、字幕、图片哈希和时间实例。历史操作的回执应单独标明来源，不能作为当前选择
已经成功的依据。资料去重、预览校验与界面操作状态各自承担不同判断。

**验证要点：** 重新提取同内容 PPT 后，旧预览应失效，新预览仍复用原讨论且不重复粘贴；
预览新片段后打开旧讨论，仍应允许准备当前片段。

## 异步接口与资源清理

### 后续任务与页面回写应分开判断

2026-11-09 · 关联源码：[副视角导入](../frontend/src/components/SecondaryViewControl.tsx)、
[对齐入口](../api/secondary_alignment.py)

**问题：** 导入请求发出后，离开页面不会撤销后端入库。把页面存活检查放在
自动对齐之前，会让成功导入漏掉后续任务；迟到响应只携带主视频 ID，又可能
给另一窗口新换的副视角启动任务。

**经验：** 页面身份只决定能否回写界面，收到成功响应后的已授权任务另行提交。
自动请求携带预期副视频及偏移，服务端在同一任务锁内先校验关联，再检查模型、
复用活动任务或入队。前端先查询再启动仍有检查与执行间隙，不能代替后端核对。
覆盖离页、切换视频、关联移除或替换及偏移修改，确认既不漏跑有效任务，
也不因旧回调启动其他目标；手动入口继续兼容原有调用。

### MCP 重试身份应随任务一同持久化

2026-11-08 · 关联源码：[课程工具](../classcue/course_tools.py)、
[批处理提交](../api/main.py)

**问题：** MCP 请求可能在后台任务已经创建后丢失响应。
仅在内存中去重或只按活动目标查询，任务结束及服务重建后可能再次执行导入或付费分析。
完整批处理的重试／恢复还会生成新的任务，直接复制原请求身份会让后续查询匹配到错误批次。

**经验：** 在任务创建事务前确定动作、参数摘要和请求标识，并随任务请求一起保存。
相同标识及参数返回原任务，标识冲突明确拒绝；新重试／恢复动作使用新标识，
界面重试不继承 MCP 的旧身份。复用现有批处理入口，统一互斥、方案快照和取消逻辑。
工具注解按实际可能发生的外部调用和覆盖行为设置，预览与执行分开说明影响。

**验证要点：** 覆盖任务结束及服务对象重建后重放、参数冲突、界面重试、
完整批次的取消与资源恢复。使用真实 stdio MCP、认证 HTTP 和原批处理引擎联通测试，
仅替换测试用 ASR／AI，不把模拟结果写成真实模型验收。

### 界面记忆不能冒充共享设置

2026-11-09 · 关联源码：[方案选择](../frontend/src/hooks/useRecallSelection.tsx)、
[课程工具](../classcue/course_tools.py)

**问题：** 界面将勾选项留在窗口本地，MCP 使用自己的默认值时，
即使 ASR 与 AI 连接一致，也不能称为沿用 APP 当前处理设置。

**经验：** 需跨入口使用的偏好应按视频库存入同一数据源。
迁移旧界面记忆时只初始化尚未保存的偏好，多窗口写入校验版本，
显式操作参数不顺带改用户偏好；空选择、首次默认及未保存的表单输入分别说明。
预览返回实际来源与版本，任务保存确定参数，响应重放不重新读取全局设置。
多步骤处理在后台保存步骤状态并按依赖执行，聊天是否继续不应决定后续步骤能否开始。

### 服务就绪不等于桌面导航就绪

2026-11-08 · 关联源码：[课程连接](../classcue/course_connection.py)

**问题：** 后端就绪标记先于窗口页面加载及启动流程收尾。
只等待服务 `ready` 就发送导航，可能在首次启动时被桌面的启动保护拒绝。
先回复导航成功再排队执行，还会越过排队期间出现的未保存状态，并隐藏窗口加载异常。
课程工具先启动 API、桌面随后复用时，两进程也不能依赖后来设置的环境变量共享更新授权。

**经验：** 复用原生命周期的服务、窗口、启动和退出状态联合判断；
工具回执只表示已请求导航，实际视频和定位时间需要单独核对。
返回工具参数错误时提供字段和有效限制，帮助 Agent 修正原操作，
避免笼统错误诱使其改变原检索范围。
导航在实际窗口调用前重查生命周期，调用抛错应明确返回失败；
需跨启动顺序共享的本机授权应由锁保护的持久凭据提供，API 固定已读取的身份，
不能以修改父进程环境代替既有子进程同步。

**验证要点：** 合成 `ready=true` 而 `starting=true` 或窗口未加载的状态序列，
确认不会过早导航；真实桌面验收核对播放器时间，不以导航请求成功代替。
另用独立子进程先构造 API，再创建桌面服务，验证实际授权路由；
窗口抛错和当前未保存状态均不能得到成功回执。
Windows WebView2 对相同 `Source` 赋值可能不产生新导航，pywebview 却会先清除就绪事件。
重复打开同一时间链接或在首页重试服务，要检查窗口实际 URL 并通过原生 WebView2
重载，不能只比较缓存 URL 或手工设置就绪。
真实验收要连续验证首次打开、同链接重开及随后不同时间跳转。
