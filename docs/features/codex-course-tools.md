## 本轮完善记录

2026-11-09，`0.7.0` 在原有课程检索、转写和完整批处理上补齐以下能力。
本文件作为课程 MCP 的持续维护说明，后续变更同步更新工具表、使用场景和边界；
测试结果另存验收记录，不以源码完成代表用户安装已经更新。

| 原来的缺口 | 现在能做什么 |
| --- | --- |
| 能启动 PPT 提取，却不能通过独立课程工具看图 | 列出指定时段 PPT，再读指定图片；也能直接取视频某秒的实际画面 |
| 能启动分析，却不能独立读取已有结果 | 分页读取考点、题目、手动定位和分析运行状态，不重新调用模型 |
| 不知道任务 ID 时无法查询 | 按活动／结束状态、包含的视频查找课程和完整批次任务 |
| 需要猜测当前保存设置 | 只读当前召回选择、ASR 选择、就绪检查缓存和 AI 模型配置；不读取密钥 |
| 只能搜课程或全库，一次一个词 | 可限定单视频，一次提交最多 8 个候选词，明确任一词／同句全部词的规则 |
| 相邻命中重复占满结果 | 默认合并间隔不超过 5 秒的命中，并在有候选的视频之间轮流返回 |
| Agent 需要自己计算上下文时间 | 返回有限相邻字幕、截断标记和可直接传给字幕读取工具的时间范围 |
| 检索返回结构缺少明确声明 | 为课程、视频、检索、字幕及新增工具声明分页和关键结果字段 |

本轮收尾统一了全库和文件夹内的 PPT 数量统计，包含辅助状态；
合并字幕按时间选取代表句，逆序写入也不会把文字配到错误的起始时间。
图像解码和编码不占用全局任务锁，慢读取期间仍可取消任务；
读取前后核对库、文件和提取记录，素材变化时要求重新读取。

### 一个使用场景：找讲解，再核对 PPT

用户说：

> 在“算法”课程里找老师讲分治的地方，也看看当时的 PPT。
> 我可能记错词了，也试一下“递归”。

Agent 可以这样完成：

1. `list_courses(query="算法")` 确定课程 ID，沿用该课程范围。
2. `search_subtitles(course_id=返回的ID, queries=["分治","递归"], match_mode="any")`。
   工具在同一范围内检索两个字面词，合并连续命中并轮流展示不同视频，
   返回每组的命中数量、时间、字幕摘要和 `context_range`。
   若用户只想查某节课，再传 `video_id`；与课程同时提供时取交集。
3. 从候选取 `video_id` 和 `context_range` 调 `read_transcript`，
   核对完整字幕，而不是仅靠搜索摘要判断老师讲了什么。
4. 调 `list_slides` 列出这段时间已有的 PPT，比较每张图的实际可见区间，
   再用 `read_slide(video_id=返回的ID, slide_id=返回的ID)` 看图。
   若要确认第 83 秒当时的板书或动画状态，调用
   `read_video_frame(video_id=返回的ID, start_seconds=83)` 看该时刻的视频画面。
5. 结合实际读到的字幕和图片回答，附视频名称、时间和播放链接。
   只有用户要求观看时才 `open_video`，检索和看图本身不打开播放器。

这里没有另一个模型替 Agent 回答：APP 只查找已保存材料、解码画面并返回证据，
Agent 负责选择候选和解释。没有 PPT 时工具返回空列表，不自动启动提取；
用户同意提取时才提交 `start_processing_sequence(steps=["extract_slides"], ...)`。
不知道此前任务的 ID 时，可用 `list_jobs` 找回后再 `get_job`。

### 检索和证据的边界

- 仍是字面检索，不是语义检索；候选词由 Agent 提供，不自动扩写同义词。
  `any` 是任一词命中；`all` 要求同一句字幕包含所有词，不跨字幕句匹配短语。
  ASR 错字和跨句切分仍可能漏搜；无结果不等于老师没有讲。
- `total` 是合并后结果数量，`total_matches` 是原始命中字幕句数量，
  `total_videos` 是命中视频数量；默认按视频轮流展示，不承诺语义相关性排名。
  `merge_gap_seconds` 可在 0–60 秒调整；0 仍合并时间重叠或相接的命中。
- 搜索上下文最多 5 句、每句最多 300 字，`context_truncated` 标记省略；
  默认扩展前后 20 秒，可设 0–120 秒。完整证据继续用 `read_transcript` 分页读取。
  查询期间每页使用一致快照，但搜索分页不锁定整个视频库；
  转写或资料变化后重新检索，不将不同轮结果当作固定快照。
- `empty_reason` 区分 `no_videos`、`no_subtitles` 和 `no_literal_match`；
  同时结合 `coverage` 说明未转写范围。翻到结果末尾的空页不等于无匹配。
- `list_slides` 返回提取状态的时间范围及真实可见区间。某页的精选状态
  不一定就是某秒画面；核对精确时刻使用 `read_video_frame`。
  图片以 MCP 图像内容返回，最长边缩至 1600 像素，不做 OCR 或模型分析，
  小字可能因缩放难以阅读；取帧仍受源视频帧率和可解码内容限制。
- `read_analysis` 读取已经保存的结果，隐藏已移除条目，区分 `manual` 与 `analysis`。
  `analysis_runs` 用来区分尚未分析和完成后零候选；手动题目可能独立于分析存在。
  长文字通过 `text_truncated` 标明截断，模型概括不能冒充教师原话。
- `list_jobs` 只覆盖课程纯转写、顺序任务和完整批次，不列模型下载、迁移等管理任务。
  `get_processing_status` 只读已有模型检查缓存，保留检查时间和 `unknown`，
  不加载模型、不检查资源余量、不验证密钥、不发起网络测试。
  AI 的 `profile_configured` 只表示模型和地址已填写，不能证明连接可用。

## 使用

正常导入本地视频、选择并准备默认 ASR 后，按
[Codex 插件安装步骤](codex-desktop-bridge.md#安装)更新插件，重新启动 ClassCue 和 Codex。
课程工具可用于任意聊天，不要求当前聊天绑定题目。
旧版安装后也可在 ClassCue 重新保存 Codex 连接，登记当前应用位置；
更新 MCP 工具和 Skill 本身仍需更新插件。

可以直接提问：

> 帮我找数据库课程里第三范式的讲解，老师怎么说？

Codex 查找课程、搜索关键词，再读附近字幕。结果不足时可自主换相关词，
不会因为空结果自动扩大到其他课程。回答附课次、时间和播放链接；
用户要求观看时才打开桌面并定位。引用是 ASR 字幕，不等于人工校对的逐字稿。
工具读取的字幕、分析文字和图片会进入当前 Codex 对话，按用户所用 Codex 服务处理，
不意味着这些材料始终仅在本机参与推理。

> 用默认模型转写数据库课程里还没字幕的视频。

转写只补缺字幕、不覆盖已有结果、不提取考点。
模型权重和环境必须已经就绪，工具不会自动准备或下载。
模型及设备设置在提交时固定，后续修改全局选择不影响该任务。
任务由 ClassCue 后台执行，Codex 查询进度；取消保留已完成字幕。
进程中断后可查到原任务，再提交原范围时跳过已有字幕，不自动启动恢复任务。
模型没有识别到可保存字幕时，该视频明确记为失败并提示检查语音，继续处理后续视频。
桌面任务中心显示“课程转写”、实际模型、逐视频状态和失败原因；
中断后未完成项显示为待转写。

> 先给这个视频补字幕，然后提取 PPT。

`start_processing_sequence` 一次提交步骤，由 APP 后台在每个视频内按顺序执行，
不依赖 Agent 持续等待。默认 `steps=["transcribe","extract_slides"]`，
也可只运行其中一步，或显式指定两步的相反顺序；步骤不能重复。
转写只使用提交时的已准备 ASR，已有字幕直接复用；PPT 使用现有提取器及缓存，
不强制覆盖、不调用考点或题目分析。失败、资源中断或取消后停止整个顺序任务，
后续步骤及其他视频不再执行，已保存字幕和 PPT 保留。
应用重启会将任务记为中断；使用新请求标识重新提交原步骤，可复用已保存产物。
聊天结束不停止任务，但 APP 所属服务必须保持运行。

> 对数据库课程做批量处理，提取中召回考点和视频题目。

Agent 先预览范围与影响，再调用应用已有完整批处理；也可指定若干视频，
或导入用户指定的本机绝对目录。完整批处理会复用已有字幕，必要时转写，
按 `analysis_modes` 执行考点召回／题目提取，可能调用已配置的 AI 服务并产生费用。
缺字幕时沿用原批处理的模型准备策略，可能下载所选模型。
这与上面的“仅补字幕、只使用已准备模型”是两种操作。

目录导入递归检查整棵目录树，沿用应用的归档规则：
校验成功后删除来源文件；内容重复时复用已有视频并保留来源。
`import_only=true` 只导入，不执行 ASR 或 AI 分析。
`force_retranscribe=true` 会按原流程替换字幕和复习结果，只用于明确的重新转写请求。

## 工具与范围

| 工具 | 输入要点 | 结果 |
| --- | --- | --- |
| `list_courses` | 可选 `query`、分页 | 课程／文件夹 ID、路径、视频数与字幕覆盖 |
| `list_videos` | 可选 `course_id`、名称、字幕状态、分页 | 视频 ID、时长、字幕状态、关联转写任务和播放链接 |
| `search_subtitles` | `query` 或 `queries`，可选课程、视频、匹配规则与分页 | 合并命中、上下文、播放链接、覆盖和无结果原因 |
| `read_transcript` | 视频 ID、起止秒数，可选继续读取游标 | 完整字幕句、时间、字幕版本、下一页位置 |
| `open_video` | 视频 ID、可选起始秒数 | 桌面导航请求结果，不冒充播放器已经完成定位 |
| `start_transcription` | `course_id` 或 `video_ids`，二选一 | 后台任务 ID、实际模型／设备、统计；无缺失则无需新建任务 |
| `start_processing_sequence` | 课程或视频集合、可选 `steps`、必填 `request_id` | 仅本地的顺序任务，默认 ASR → PPT；逐视频、逐步骤保存状态，失败即停止 |
| `preview_batch` | `course_id`、`video_ids`、`folders` 三选一，可附处理选项 | 范围、字幕覆盖、可用分析方案、导入与 AI 影响；不创建任务或调用模型 |
| `start_batch_processing` | 同预览参数，另需 `request_id` | 提交已有完整批处理；返回持久任务 ID、模型、方案、统计及结果 |
| `retry_batch` | 完整批次 `job_id`、新动作的 `request_id` | 重试失败、中断或等待 AI 的未完成项，复用字幕和已完成方案 |
| `resume_batch` | 资源暂停的完整批次 `job_id`、新动作的 `request_id` | 使用已有恢复流程创建续跑任务，资源问题需先解除 |
| `get_job` | `job_id`，顺序任务或完整批次明细可分页 | 状态、进度、统计、逐项结果及后续动作 |
| `cancel_job` | `job_id` | 请求停止纯转写、顺序任务或完整批次；保留已保存结果，不开放其他类型任务取消 |
| `list_slides` | 视频 ID、起止秒数、分页 | 时段内已提取的 PPT 状态、可见区间和图片 ID，不启动提取 |
| `read_slide` | 视频 ID、PPT 图片 ID | 原生 MCP 图像及尺寸，校验图片所属视频 |
| `read_video_frame` | 视频 ID、秒数 | 指定时刻的实际视频画面，不要求已有 PPT |
| `read_analysis` | 视频 ID、可选方案和分页 | 已保存考点／题目、来源、复习状态及分析运行状态 |
| `list_jobs` | 可选状态、视频 ID、分页 | 找回任务 ID；活动任务优先，不自动恢复处理 |
| `get_processing_status` | 无 | 当前保存的处理选择、ASR 检查缓存和非敏感 AI 模型配置 |

完整批处理的 `options` 支持 `analysis_modes`、`asr_model_id`、`keywords`、
`use_keyword_prefilter`、`filter_formula_noise`、`filter_formula` 和 `force_retranscribe`。
省略 `analysis_modes` 时沿用 APP 已保存方案；首次无偏好时为中召回。
可选择高／中／低召回、题目提取、旧兼容方案或有效自定义方案；
预览返回可选方案 ID。处理直接复用应用现有入口，没有另建分析引擎。

### APP 与 MCP 共用处理方案

APP 将召回／题目提取选择保存在当前视频库的数据库中。
升级后首次打开新版界面，会把原来同库 `localStorage` 的选择迁入后端；
已有后端偏好时不覆盖，多个窗口同时迁移时只接受首个成功写入。
空选择仍为空，分析时明确拒绝，不悄悄回退中召回；自定义方案保存及执行时均校验有效性。
界面保存失败会显示错误，可重新读取；窗口重新聚焦或前台每 15 秒同步已保存选择。
多窗口保存携带版本号，过期写入被拒绝，避免覆盖较新的选择。

预览的 `analysis_modes_source` 区分 `app_saved`、`first_use_default`、`explicit`
和仅导入时的 `not_used`，并返回 `recall_selection_revision`。
按预览提交时将该版本作为 `expected_recall_revision`；APP 偏好变化则要求重新预览。
不提供版本时，以提交时的已保存偏好为准；显式传入方案只覆盖本次任务，不改偏好。
任务创建时保存实际处理方案，请求重放也不重新读取偏好。

读写偏好接口为 `GET/PUT /api/settings/recall-selection`，写入包含
`library_id`、`analysis_modes` 和 `expected_revision`。
ASR、设备及 AI 连接继续沿用应用已有设置。关键词、过滤表达式与覆盖转写等
页面临时输入不是全局偏好，MCP 仍需显式指定，不能宣称读到了未保存的表单状态。

启动、重试和恢复必须携带 8–100 字符的 `request_id`，只允许字母、数字、下划线和连字符。
请求标识与动作、参数摘要在创建任务时一同持久化。
工具响应丢失时，以同一标识及相同参数重试会返回原任务，即使任务已经结束或服务对象重建；
同标识换参数会明确报错。新的处理动作使用新标识，查询进度只用 `get_job`。
重试和恢复返回新的任务 ID，后续查询应使用新 ID；当前 AI 连接按原批处理规则取用。
取消返回“正在停止”仅表示收到请求，需继续查询终态。

`course_id` 使用工具返回的原值：

- 已绑定课程返回原课程 ID，普通文件夹返回 `folder:<ID>`；二者均包含所有子目录。
- 同一个文件夹只返回一个条目；每个子文件夹也可单独作为范围，路径用于区分同名目录。
- `root` 仅表示根目录下未归类视频，不包含子目录。
- 省略只读工具的课程范围表示全库；转写必须明确课程或视频集合。
- 列表、搜索和转写复用相同的范围规则，副视角附属来源不参与。

时间统一使用秒，带小数。列表和搜索每页默认 20、最多 50；
字幕每页最多 100 句、12,000 个原文字符，边界句保留原句与原时间。
继续读取需同时传入 `offset` 和 `transcript_version`，字幕变化时要求重新读取。
搜索不提供语义或纠错保证，单段内字面匹配可能漏掉跨句词组。
完整批次逐项结果每页默认及最多 50 项，使用 `has_more`／`next_offset` 继续读取；
总体统计始终覆盖完整批次。预览只附前 50 个视频的名称及 ID，并返回是否截断。

## 本地连接

保留现有 stdio MCP 服务，由短生命周期 Python 桥接访问本地 HTTP 接口；
不要求 Agent 提供机器路径、端口或访问令牌。
安装器和应用连接设置登记应用位置；每次调用重新读取配置。
后端接口是 `POST /api/course-tools/{tool}`，
请求包含 `library_id` 与 `arguments`，通过本地 Bearer 凭据校验。
凭据只保存于应用忽略的运行目录，不作为工具结果返回。

服务未运行时通过既有启动器启动静态页面 API，不打开桌面或浏览器。
已有服务必须与登记的视频库及实例身份一致，不替换其他库的服务。
用户希望观看时再启动或复用桌面，通过受认证的 IPC 请求导航；
有未保存修改或桌面未就绪时返回错误，不覆盖用户操作。

任务写入既有 `processing_jobs`：纯转写为 `course_transcribe`，
完整批处理为原有 `batch_video_process`，顺序任务为 `course_sequence`。
MCP 可查询、取消和重试界面创建的完整批次。
纯转写重复提交相同活动目标返回原任务，完整批处理按 `request_id` 复用；
其他任务冲突继续遵循应用原有互斥规则。
任务队列中的视频受文件变更保护，不因尚未轮到该视频而允许移动或改名。

工具输入使用对象 schema、排斥未知字段并校验互斥目标；输出同时提供
`structuredContent` 和兼容文本，声明 `outputSchema`。业务错误通过 MCP `isError` 返回。
完整批处理、重试和恢复标记为有写入影响、可能访问外部服务；
带请求标识的动作标记为幂等。预览为只读，取消不承诺即时终止。

## 升级边界

本功能新增插件模块和 Skill 路径。当前程序的发行路径校验已包含两者，
提交基线中的旧更新助手仍会拒绝这些新增路径；新包内的校验器无法改变旧助手的解包行为。
下一次发行前需核对实际旧发行包并安排完整新包的手动升级或过渡版本。
本次没有执行发行或真实原地升级，不能将当前清单校验通过视为旧版升级通过。
