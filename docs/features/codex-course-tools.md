### 可选的本地字幕语义检索

`search_library` 默认仍按字面和发音候选查找。显式提供 `semantic_query` 时，
使用本地 Qwen3-Embedding-0.6B 召回字幕片段；与一组字面词同传则以 RRF 合并排名。
字面组合只约束字面分支；课程、视频、时间与排除词约束两路，不自动扩大范围。
没有关键词重合的语义证据仍返回原字幕、原记录 ID、时间与 `context_range`，
`match_type=semantic`，`semantic_similarity` 是余弦相似度，不是回答置信度。
模型不自动纠正 ASR，不生成摘要或替 Agent 回答，不索引 PPT、上传资料或图片。

APP“设置 → 课程检索”直接显示 CPU／GPU 两个单选项，显式准备独立模型环境，
再选择课程建立或更新索引。模型从官方 ModelScope 下载并核对 SHA-256，
权重和隔离环境使用已有模型存储根目录，不向主服务或 ASR 环境安装 PyTorch。
CPU/GPU 使用同一份权重和相互独立的运行环境，首次检测到 NVIDIA GPU 时默认 GPU，
否则默认 CPU；
已有设备选择保留，切换已准备设备复用本地环境，不重复下载权重。
推理仅读取本地权重，字幕不发往模型服务。
准备前显示所选设备尚需下载的预计大小；已准备环境和共享权重不重复计算。
预计值基于固定版本依赖，实际下载量可能因缓存和依赖变化而不同。
显式下载后显示当前文件、已下载字节和速度；依赖安装没有字节进度时显示安装阶段，
不伪造百分比。缓存区同时显示 GPU 环境、CPU 环境和共享权重各自的占用，
没有文件时显示“无”；未准备但仍有文件时保留残留缓存状态，不当作已经清空。
可选择仅使用 GPU 并清理 CPU 缓存，或仅使用 CPU 并清理 GPU 缓存；
保留设备需事先准备，验证切换成功后再删除另一套环境。卸载 RAG 提示 AI 检索能力可能下降，
清除两套环境与模型文件，保留原字幕、PPT、课程索引及
ASR 共用下载缓存。清理沿用后台任务，开始后不提供暂停或停止按钮；
若意外中断，重新检查实际剩余缓存并允许继续清理。
全局搜索弹窗增加“原文／语义”切换，默认原文；语义结果显示尚未索引的视频数。

`get_semantic_status` 只读模型和范围覆盖；`start_semantic_index` 在现有后台任务队列
建立已保存字幕的索引，可用 `get_job`／`cancel_job` 查询或停止。
`0.13.0` 增加 `start_semantic_prepare`（仅准备或切换模型）和
`start_semantic_setup`（准备模型后为明确课程／视频建立索引）。
两者要求持久 `request_id`；响应丢失后同参数同标识重试返回原任务，
新操作或失败后重新处理使用新标识。可选 `device=cpu|cuda`，
省略时捕获当前设备选择。普通查找不授权后台下载或索引；
用户明确要求开启某课程语义检索时可直接提交该范围的 setup。
任务保存目标视频列表，取消或准备失败不会继续建立索引；
已完成视频保留，下次重试复用。HTTP 对应
`POST /api/semantic/prepare` 与 `POST /api/semantic/setup`，
APP 可省略 `request_id`，由接口生成。
每块最多 500 字，按原字幕句和最多 90 秒讲解范围组合，保留少量句级重叠；
超长句切片保留原句时间，不虚构字符时间戳。
每个视频计算完成后原子发布，停止或失败保留此前完成的视频，重试复用当前版本结果。
字幕增删改使对应视频索引失效，发布前重新核对原文；模型文件指纹和分块版本隔离缓存。
升级启动仅建立空表，不自动向量化整库。

搜索仅读取已建索引，不隐式下载或建立索引；后台重型任务期间拒绝语义推理，
原文搜索仍可使用。模型空闲一分钟或其他重型任务开始前释放工作进程。
`semantic_coverage.pending_videos` 与缺字幕分别报告；覆盖不全不能断言课堂没有内容。
每次最多返回 100 个语义候选，`semantic_candidates_truncated` 单独标明截断，
`total` 是候选片段数，`total_is_exact=false`，不表示语义相关内容的完整数量。
分页继续使用 `snapshot_id`，来源、参数或模型变化后重新搜索。
第一版不增加重排模型，也不以合成协议测试或单个案例声称普遍提高召回率。

### 按需字幕发音容错

2026-11-10，`0.11.0` 在同一个 `search_library` 增加 `phonetic_mode`：

| 策略 | 行为 |
| --- | --- |
| `auto`（默认） | 先查四类资料的字面命中；完整搜索无结果时，在原范围补查字幕同音候选 |
| `off` | 只查字面，不转换发音或准备发音索引 |
| `always` | 主动补查字幕同音候选，字面结果优先；适合用户提示同音错字或现有结果不相关 |

用户说“闭包可能被 ASR 写成同音字”时，可调用
`search_library(query="闭包", phonetic_mode="always")`。
用户明确指出错词“B包”时，先用 `queries=["闭包","B包"]` 做字面候选；
多个概念时，把原词和错词放进同一个 `term_groups` 组。
无需为每门课维护术语表，不额外调用 LLM、ASR 或音频服务。

本地使用 pypinyin 的词组读音，忽略声调，但完整匹配音节序列；
至少 2、最多 24 个音节，不启用任意编辑距离或模糊近音。
孤立英文字母按通用读音映射，例如 `B包 → bi bao`；普通英文单词、
数字和标点是边界，不逐字母拼读英文，不跨字幕句拼接单个词。
不枚举全部多音字读法，也不承诺恢复漏字、口音、任意英文或语义。
仅字幕使用发音候选；目录、书签、考点与排除词仍按字面匹配。

`phonetic_search_used` 表示本轮实际启用了发音候选，`phonetic_terms`
列出可转换的查询词。顶层 `match_type` 此时为 `phonetic_passage`，
具体片段和证据另用 `literal`／`phonetic`／`mixed` 区分实际命中方式。
证据保留原字幕、原记录和时间；`matched_terms` 包含发音命中的查询词，
`literal_matched_terms` 只列原文包含的词。每项证据最多 8 个 `phonetic_matches`，
其中保留查询词、原文词、音节、相对于摘录的字符位置及
`requires_verification=true`；详情省略时标记 `phonetic_matches_truncated`。
例如原文仍是“这里的 B包可以访问外部变量”，不能据此声称字幕已纠正为“闭包”。
Agent 应接 `read_transcript`、按需查看 PPT 后确认含义。

发音索引是库内可再生缓存。升级启动时只建空表，不转换整库；
首次发音搜索只补当前课程／视频／时间范围内的缺失或旧版本条目，
每次最多处理 4000 句或约 100 万原文字符（完成当前句后检查字符预算）。
未变化的字幕持久复用索引，改字、替换或删除字幕时自动失效。
转换在写事务外计算，入库前核对原文，防止并发修改留下旧读音。
缓存准备后重新取得一致的读取快照，任务控制锁不包住索引准备或检索。

`phonetic_index_pending>0` 表示范围内仍有待建索引的句子，返回
`search_complete=false`、`total_is_exact=false`，空结果为 `incomplete_search`。
可同参数从第一页重试，较大的库优先限定课程，不沿用未完成索引的旧快照翻页。
候选达到上限仍另报 `candidate_truncated_sources`。任何不完整搜索都不能断言没有讲解。
APP 原有搜索界面与旧搜索接口继续使用原字面规则。

### 统一视频库检索

2026-11-10，`0.10.0` 将主搜索入口统一为 `search_library`，默认查询四类视频库资料：
`catalog`（视频名称、课程及文件夹路径）、`bookmarks`（人工书签和整段提醒）、
`subtitles`（原始字幕）、`analysis`（已保存考点、视频题目和手动定位）。
不涉及上传资料全文、PDF 或 PPT OCR，不自动调用模型、转写或建立向量索引。
原 `search_subtitles`、`search_bookmarks` 保留后端与旧调用兼容，不再出现在 MCP 工具列表中。
课程和视频列表继续用于浏览、确认身份及批处理选取。

- `query` 为一个字面词或短语；`queries` 最多 8 个词，默认 `any`，可用 `all`。
- `term_groups` 表达组内任一、组间全部，例如
  `[["范式","规范化"],["冗余","分解"]]`。最多 6 组、每组 8 词、总计 32 词，
  与 `query`、`queries` 三选一；使用它时不再设置 `match_mode=all`。
- 字幕允许在 `window_seconds` 内跨句满足组合，默认 45 秒、最多 120 秒。
  单个短语仍须在原句内出现；书签和分析在单条记录内满足组合。
  不将目录或其他来源拼成教师原话。相邻命中合并受窗口上限约束；
  单句字幕本身超过窗口时保留原句时间，不伪造字级边界。
- `exclude_terms` 最多 8 词，排除含词的匹配记录或字幕片段。
  片段内没有正向命中词的句子同样参与排除检查；外延上下文不作为匹配正文。
  相邻字幕或跨来源片段合并前也校验完整范围，遇到排除词时保留分开的合法命中。
- `course_id`、`video_id` 同时提供时取交集；`start_seconds/end_seconds` 须成对提供，
  仅保留相交的时间证据，不返回目录及无时间提醒，不自动扩大搜索范围。
- 排序考虑词覆盖、片段紧凑程度与多来源汇合，`diverse=true` 对同一视频后续结果
  适度降权。分数是检索启发式，不是语义相关性或回答置信度。

返回统一的视频片段，包含 `result_id`、目录、可空 `position_seconds`、
`context_range`、播放链接、命中词及最多 6 项 `evidence`。
每项证据保留来源、原记录 ID、原时间、最多 500 字摘录及截断标记；
`asr_transcript`、`user_bookmark`、`manual_marker`、`saved_analysis`、`video_metadata`
分别代表 ASR 字幕、用户备注、手动定位、模型分析和目录信息。
名称与无时间提醒保留空时间，不把视频开头当作讲解位置；
时长未知时不返回无法确认的字幕读取范围。
先选择候选，再用 `read_transcript(video_id, **context_range)` 核对上下文，
按需用 `list_slides`、`read_slide` 或 `read_video_frame` 看图。

各来源在同一 SQLite 读取快照内查询。每页默认 20、最多 50 条；
翻页须原样提供 `snapshot_id`，资料或查询条件变化时从第一页重新检索。
每个来源最多收集 4000 个候选，超出时返回 `search_complete=false`、
`total_is_exact=false` 和 `candidate_truncated_sources`；
`total` 与 `source_counts` 仅描述已收集结果。应收紧课程、视频、时间或关键词，
不能把不完整查询的空结果解释为没有内容。覆盖情况单独返回。
检索在全局任务锁之外执行，返回前核对视频库身份，不阻塞任务取消。

例如用户说“找老师讲过怎样通过规范化减少重复存储的那一段”，Agent 可在确认课程后调用：

```json
{
  "course_id": "<list_courses 返回的 ID>",
  "term_groups": [["规范化", "范式"], ["冗余", "重复存储", "分解"]],
  "limit": 10
}
```

候选词由 Codex 提出，没有命中时可在同范围换词；
`0.11.0` 起可按上节规则补查同音候选，不承诺 ASR 纠错或语义召回。
APP 原有搜索界面与其字面查询规则保持原有行为。

2026-11-09，`0.7.0` 在原有课程检索、转写和完整批处理上补齐以下能力。
本文件作为课程 MCP 的持续维护说明，后续变更同步更新工具表、使用场景和边界；
测试结果另存验收记录，不以源码完成代表用户安装已经更新。

| 原来的缺口 | 现在能做什么 |
| --- | --- |
| 能启动 PPT 提取，却不能通过独立课程工具看图 | 列出指定时段 PPT，再读指定图片；也能直接取视频某秒的实际画面 |
| 能启动分析，却不能独立读取已有结果 | 分页读取考点、题目、手动定位和分析运行状态，不重新调用模型 |
| 不知道任务 ID 时无法查询 | 按活动／结束状态、包含的视频查找课程和完整批次任务 |
| 需要猜测当前保存设置 | 只读当前召回选择、ASR 选择、就绪检查缓存和 AI 模型配置；不读取密钥 |
| 只能搜课程或全库，一次一个词 | 可限定单视频，一次提交最多 8 个候选词，明确任一词／同句全部词的规则 |
| 相邻命中重复占满结果 | 默认合并间隔不超过 5 秒的命中，并在有候选的视频之间轮流返回 |
| Agent 需要自己计算上下文时间 | 返回有限相邻字幕、截断标记和可直接传给字幕读取工具的时间范围 |
| 检索返回结构缺少明确声明 | 为课程、视频、检索、字幕及新增工具声明分页和关键结果字段 |

本轮收尾统一了全库和文件夹内的 PPT 数量统计，包含辅助状态；
合并字幕按时间选取代表句，逆序写入也不会把文字配到错误的起始时间。
图像解码和编码不占用全局任务锁，慢读取期间仍可取消任务；
读取前后核对库、文件和提取记录，素材变化时要求重新读取。

### 从自己的书签找回讲解

`0.9.0` 曾新增只读工具 `search_bookmarks`，直接读取 APP 中用户手动添加的复习书签。
`0.10.0` 起面向 Agent 改用 `search_library(sources=["bookmarks"], ...)`；
以下保留旧接口兼容行为。
例如用户说“我记得有个视频讲解了自注意力”，Agent 可先调用
`search_bookmarks(query="自注意力")`，从“自注意力：Q/K/V 计算示例”这样的合成提醒
找回视频、原时间点和播放链接，再用返回的 `context_range` 读取附近字幕核对。
书签即使没有字幕也能找到；备注是用户提醒，不是教师原话或操作指令。

只对备注做大小写不敏感的字面匹配，不把视频名或字幕命中混作书签命中。
支持 `query` 或最多 8 个 `queries`，不可同时提供；`any` 命中任一词，
`all` 要求同一条备注含全部词。不提供两者时分页浏览全部书签，包含空备注。
可限定 `course_id`、`video_id`，二者同时提供取交集；不因无结果自动扩大范围。
候选词由 Agent 选择，不运行语义检索或第二套问答模型。

返回 `bookmark_id`、完整 `note`、视频名称、文件夹路径、可空的 `position_seconds`、
字幕状态、播放链接及创建／更新时间。无时间点表示整段视频提醒，
此时 `context_range` 同样为空，不能将链接默认打开视频开头解释为讲解从零秒开始。
有时间点且视频时长已知时，默认附前后各 30 秒的读取范围，
`context_seconds` 可设为 1–120，范围限制在视频时长内；
时长未知时不提供字幕读取范围，附近字幕仍需用 `read_transcript` 实际读取。

结果按书签 ID 倒序分页，每页默认 20、最多 50；`total` 和 `total_videos`
统计全部命中，`searched_bookmarks` 表示本范围检查的书签数。
`empty_reason=no_bookmarks` 表示范围内没有书签，`no_literal_match` 表示有书签但备注未命中；
翻页超过末尾不冒充无命中。无结果可在同范围换词或搜索字幕，不能据此断言视频没有讲过。
复用现有书签存储，不建立独立索引；APP 编辑、删除、视频改名或移动后下次读取立即反映，
附属副视角与已删除视频不参与。不开放书签写入，不启动转写、PPT 提取或 AI 请求。

### 一个使用场景：找讲解，再核对 PPT

用户说：

> 在“算法”课程里找老师讲分治的地方，也看看当时的 PPT。
> 我可能记错词了，也试一下“递归”。

Agent 可以这样完成：

1. `list_courses(query="算法")` 确定课程 ID，沿用该课程范围。
2. `search_library(course_id=返回的ID, queries=["分治","递归"], match_mode="any")`。
   工具在同一范围内检索多个来源，合并相近命中并适度分散视频，
   返回片段命中词、来源证据、可空时间和 `context_range`。
   若用户只想查某节课，再传 `video_id`；与课程同时提供时取交集。
3. 从候选取 `video_id` 和 `context_range` 调 `read_transcript`，
   核对完整字幕，而不是仅靠搜索摘要判断老师讲了什么。
4. 调 `list_slides` 列出这段时间已有的 PPT，比较每张图的实际可见区间，
   再用 `read_slide(video_id=返回的ID, slide_id=返回的ID)` 看图。
   若要确认第 83 秒当时的板书或动画状态，调用
   `read_video_frame(video_id=返回的ID, start_seconds=83)` 看该时刻的视频画面。
5. 结合实际读到的字幕和图片回答，附视频名称、时间和播放链接。
   只有用户要求观看时才 `open_video`，检索和看图本身不打开播放器。

这里没有另一个模型替 Agent 回答：APP 只查找已保存材料、解码画面并返回证据，
Agent 负责选择候选和解释。没有 PPT 时工具返回空列表，不自动启动提取；
用户同意提取时才提交 `start_processing_sequence(steps=["extract_slides"], ...)`。
不知道此前任务的 ID 时，可用 `list_jobs` 找回后再 `get_job`。

### 按学习任务主动核实

课程 Skill 将搜索结果作为候选入口。用户要求确认某个课堂说法或寻找更合适的讲解时，
Agent 先读相关片段的完整字幕，比较是否切题、条件是否一致、解释是否完整，
不把检索最高分直接当作最佳知识点。
若遇到 ASR 术语歧义、“看这个图”等画面指代、公式代码缺失或候选间冲突，
主动查询该时段 PPT 并读取相关图片，无需用户逐项指挥。
没有已提取 PPT 而仍需画面核实时，可以直接读取对应秒数的视频帧，
不自动开始 PPT 提取。选择图片时按实际可见区间核对，不把晚出现的答案算作早已展示。

证据足够时停止补查，普通定位或清晰完整的文字解释不强制取图。
存在多个候选时推荐更能回答当前问题、证据更完整的片段；
仍不能确认时说明疑点，不宣称遍历了全库或找到了绝对最佳。
这是供 Agent 决策的 Skill 指引，不是检索后端固定执行的取图流水线；
实际运行是否正确遵循，仍需结合具体学习任务观察，不能由静态校验推定。

### 检索和证据的边界

- 以字面检索为基础，可按需补充字幕同音候选；候选词由 Agent 提供，不自动扩写同义词。
  `any` 是任一词命中；`all` 及关键词组合允许在有限字幕片段内跨句满足，
  单个短语仍不跨字幕句拼接。
  ASR 错字和跨句切分仍可能漏搜；无结果不等于老师没有讲。
- `total` 是合并后片段数，`source_counts` 是各来源合并前的匹配记录／片段数，
  `total_videos` 是命中视频数；候选截断时均不代表完整全库统计。
- 搜索证据最多 6 项、每项 500 字，分别提供文本和证据截断标记；
  上下文范围默认扩展前后 15 秒，可设 0–120 秒。完整字幕用 `read_transcript` 分页读取。
  每次查询使用一致快照，翻页核对结果指纹；转写或资料变化后重新检索。
- `empty_reason` 区分 `no_videos`、`no_matching_content` 和 `incomplete_search`；
  同时结合 `coverage` 说明未转写范围。翻到结果末尾的空页不等于无匹配。
- `list_slides` 返回提取状态的时间范围及真实可见区间。某页的精选状态
  不一定就是某秒画面；核对精确时刻使用 `read_video_frame`。
  图片以 MCP 图像内容返回，最长边缩至 1600 像素，不做 OCR 或模型分析，
  小字可能因缩放难以阅读；取帧仍受源视频帧率和可解码内容限制。
  `0.12.0` 修复 Codex 只收到尺寸、收不到画面的情况：读图工具仅返回
  `content` 中的文字元数据和实际图像块，不再附带会覆盖图像的 `structuredContent`。
  无需重新提取 PPT，但已安装的插件需要更新并重新加载 MCP 服务。
- `read_analysis` 读取已经保存的结果，隐藏已移除条目，区分 `manual` 与 `analysis`。
  `analysis_runs` 用来区分尚未分析和完成后零候选；手动题目可能独立于分析存在。
  长文字通过 `text_truncated` 标明截断，模型概括不能冒充教师原话。
- `list_jobs` 只覆盖课程纯转写、顺序任务和完整批次，不列模型下载、迁移等管理任务。
  `get_processing_status` 只读已有模型检查缓存，保留检查时间和 `unknown`，
  不加载模型、不检查资源余量、不验证密钥、不发起网络测试。
  AI 的 `profile_configured` 只表示模型和地址已填写，不能证明连接可用。

## 使用

正常导入本地视频、选择并准备默认 ASR 后，按
[Codex 可选配套安装与更新](codex-plugin-install.md)更新插件，重新启动 ClassCue 和 Codex。
课程工具可用于任意聊天，不要求当前聊天绑定题目。
旧版安装后也可在 ClassCue 重新保存 Codex 连接，登记当前应用位置；
更新 MCP 工具和 Skill 本身仍需更新插件。

可以直接提问：

> 帮我找数据库课程里第三范式的讲解，老师怎么说？

Codex 查找课程、搜索关键词，再读附近字幕。结果不足时可自主换相关词，
不会因为空结果自动扩大到其他课程。回答附课次、时间和播放链接；
用户要求观看时才打开桌面并定位。引用是 ASR 字幕，不等于人工校对的逐字稿。
工具读取的字幕、分析文字和图片会进入当前 Codex 对话，按用户所用 Codex 服务处理，
不意味着这些材料始终仅在本机参与推理。

> 用默认模型转写数据库课程里还没字幕的视频。

转写只补缺字幕、不覆盖已有结果、不提取考点。
模型权重和环境必须已经就绪，工具不会自动准备或下载。
模型及设备设置在提交时固定，后续修改全局选择不影响该任务。
任务由 ClassCue 后台执行，Codex 查询进度；取消保留已完成字幕。
进程中断后可查到原任务，再提交原范围时跳过已有字幕，不自动启动恢复任务。
模型没有识别到可保存字幕时，该视频明确记为失败并提示检查语音，继续处理后续视频。
桌面任务中心显示“课程转写”、实际模型、逐视频状态和失败原因；
中断后未完成项显示为待转写。

> 先给这个视频补字幕，然后提取 PPT。

`start_processing_sequence` 一次提交步骤，由 APP 后台在每个视频内按顺序执行，
不依赖 Agent 持续等待。默认 `steps=["transcribe","extract_slides"]`，
也可只运行其中一步，或显式指定两步的相反顺序；步骤不能重复。
转写只使用提交时的已准备 ASR，已有字幕直接复用；PPT 使用现有提取器及缓存，
不强制覆盖、不调用考点或题目分析。失败、资源中断或取消后停止整个顺序任务，
后续步骤及其他视频不再执行，已保存字幕和 PPT 保留。
应用重启会将任务记为中断；使用新请求标识重新提交原步骤，可复用已保存产物。
聊天结束不停止任务，但 APP 所属服务必须保持运行。

> 对数据库课程做批量处理，提取中召回考点和视频题目。

Agent 先预览范围与影响，再调用应用已有完整批处理；也可指定若干视频，
或导入用户指定的本机绝对目录。完整批处理会复用已有字幕，必要时转写，
按 `analysis_modes` 执行考点召回／题目提取，可能调用已配置的 AI 服务并产生费用。
缺字幕时沿用原批处理的模型准备策略，可能下载所选模型。
这与上面的“仅补字幕、只使用已准备模型”是两种操作。

目录导入递归检查整棵目录树，沿用应用的归档规则：
校验成功后删除来源文件；内容重复时复用已有视频并保留来源。
`import_only=true` 只导入，不执行 ASR 或 AI 分析。
`force_retranscribe=true` 会按原流程替换字幕和复习结果，只用于明确的重新转写请求。

## 工具与范围

| 工具 | 输入要点 | 结果 |
| --- | --- | --- |
| `list_courses` | 可选 `query`、分页 | 课程／文件夹 ID、路径、视频数与字幕覆盖 |
| `list_videos` | 可选 `course_id`、名称、字幕状态、分页 | 视频 ID、时长、字幕状态、关联转写任务和播放链接 |
| `search_library` | `query`／`queries`／`term_groups` 三选一，可选 `phonetic_mode`、来源、课程、视频、时间、排除词、片段窗口及快照分页 | 统一片段、来源证据、发音假设、相关性分数、可空秒数、播放链接、覆盖与截断及索引待建状态 |
| `read_transcript` | 视频 ID、起止秒数，可选继续读取游标 | 完整字幕句、时间、字幕版本、下一页位置 |
| `open_video` | 视频 ID、可选起始秒数 | 桌面导航请求结果，不冒充播放器已经完成定位 |
| `start_transcription` | `course_id` 或 `video_ids`，二选一 | 后台任务 ID、实际模型／设备、统计；无缺失则无需新建任务 |
| `start_processing_sequence` | 课程或视频集合、可选 `steps`、必填 `request_id` | 仅本地的顺序任务，默认 ASR → PPT；逐视频、逐步骤保存状态，失败即停止 |
| `preview_batch` | `course_id`、`video_ids`、`folders` 三选一，可附处理选项 | 范围、字幕覆盖、可用分析方案、导入与 AI 影响；不创建任务或调用模型 |
| `start_batch_processing` | 同预览参数，另需 `request_id` | 提交已有完整批处理；返回持久任务 ID、模型、方案、统计及结果 |
| `retry_batch` | 完整批次 `job_id`、新动作的 `request_id` | 重试失败、中断或等待 AI 的未完成项，复用字幕和已完成方案 |
| `resume_batch` | 资源暂停的完整批次 `job_id`、新动作的 `request_id` | 使用已有恢复流程创建续跑任务，资源问题需先解除 |
| `get_job` | `job_id`，顺序任务或完整批次明细可分页 | 状态、进度、统计、逐项结果及后续动作 |
| `cancel_job` | `job_id` | 请求停止纯转写、顺序任务或完整批次；保留已保存结果，不开放其他类型任务取消 |
| `list_slides` | 视频 ID、起止秒数、分页 | 时段内已提取的 PPT 状态、可见区间和图片 ID，不启动提取 |
| `read_slide` | 视频 ID、PPT 图片 ID | 原生 MCP 图像及尺寸，校验图片所属视频 |
| `read_video_frame` | 视频 ID、秒数 | 指定时刻的实际视频画面，不要求已有 PPT |
| `read_analysis` | 视频 ID、可选方案和分页 | 已保存考点／题目、来源、复习状态及分析运行状态 |
| `list_jobs` | 可选状态、视频 ID、分页 | 找回任务 ID；活动任务优先，不自动恢复处理 |
| `get_processing_status` | 无 | 当前保存的处理选择、ASR 检查缓存和非敏感 AI 模型配置 |

完整批处理的 `options` 支持 `analysis_modes`、`asr_model_id`、`keywords`、
`use_keyword_prefilter`、`filter_formula_noise`、`filter_formula` 和 `force_retranscribe`。
省略 `analysis_modes` 时沿用 APP 已保存方案；首次无偏好时为中召回。
可选择高／中／低召回、题目提取、旧兼容方案或有效自定义方案；
预览返回可选方案 ID。处理直接复用应用现有入口，没有另建分析引擎。

### APP 与 MCP 共用处理方案

APP 将召回／题目提取选择保存在当前视频库的数据库中。
升级后首次打开新版界面，会把原来同库 `localStorage` 的选择迁入后端；
已有后端偏好时不覆盖，多个窗口同时迁移时只接受首个成功写入。
空选择仍为空，分析时明确拒绝，不悄悄回退中召回；自定义方案保存及执行时均校验有效性。
界面保存失败会显示错误，可重新读取；窗口重新聚焦或前台每 15 秒同步已保存选择。
多窗口保存携带版本号，过期写入被拒绝，避免覆盖较新的选择。

预览的 `analysis_modes_source` 区分 `app_saved`、`first_use_default`、`explicit`
和仅导入时的 `not_used`，并返回 `recall_selection_revision`。
按预览提交时将该版本作为 `expected_recall_revision`；APP 偏好变化则要求重新预览。
不提供版本时，以提交时的已保存偏好为准；显式传入方案只覆盖本次任务，不改偏好。
任务创建时保存实际处理方案，请求重放也不重新读取偏好。

读写偏好接口为 `GET/PUT /api/settings/recall-selection`，写入包含
`library_id`、`analysis_modes` 和 `expected_revision`。
ASR、设备及 AI 连接继续沿用应用已有设置。关键词、过滤表达式与覆盖转写等
页面临时输入不是全局偏好，MCP 仍需显式指定，不能宣称读到了未保存的表单状态。

启动、重试和恢复必须携带 8–100 字符的 `request_id`，只允许字母、数字、下划线和连字符。
请求标识与动作、参数摘要在创建任务时一同持久化。
工具响应丢失时，以同一标识及相同参数重试会返回原任务，即使任务已经结束或服务对象重建；
同标识换参数会明确报错。新的处理动作使用新标识，查询进度只用 `get_job`。
重试和恢复返回新的任务 ID，后续查询应使用新 ID；当前 AI 连接按原批处理规则取用。
取消返回“正在停止”仅表示收到请求，需继续查询终态。

`course_id` 使用工具返回的原值：

- 已绑定课程返回原课程 ID，普通文件夹返回 `folder:<ID>`；二者均包含所有子目录。
- 同一个文件夹只返回一个条目；每个子文件夹也可单独作为范围，路径用于区分同名目录。
- `root` 仅表示根目录下未归类视频，不包含子目录。
- 省略只读工具的课程范围表示全库；转写必须明确课程或视频集合。
- 列表、搜索和转写复用相同的范围规则，副视角附属来源不参与。

时间统一使用秒，带小数。列表和搜索每页默认 20、最多 50；
字幕每页最多 100 句、12,000 个原文字符，边界句保留原句与原时间。
继续读取需同时传入 `offset` 和 `transcript_version`，字幕变化时要求重新读取。
搜索不提供语义或纠错保证；多词组合允许跨句，单个短语跨句切分仍可能漏搜。
完整批次逐项结果每页默认及最多 50 项，使用 `has_more`／`next_offset` 继续读取；
总体统计始终覆盖完整批次。预览只附前 50 个视频的名称及 ID，并返回是否截断。

## 本地连接

保留现有 stdio MCP 服务，由短生命周期 Python 桥接访问本地 HTTP 接口；
不要求 Agent 提供机器路径、端口或访问令牌。
安装器和应用连接设置登记应用位置；每次调用重新读取配置。
后端接口是 `POST /api/course-tools/{tool}`，
请求包含 `library_id` 与 `arguments`，通过本地 Bearer 凭据校验。
凭据只保存于应用忽略的运行目录，不作为工具结果返回。

服务未运行时通过既有启动器启动静态页面 API，不打开桌面或浏览器。
已有服务必须与登记的视频库及实例身份一致，不替换其他库的服务。
用户希望观看时再启动或复用桌面，通过受认证的 IPC 请求导航；
有未保存修改或桌面未就绪时返回错误，不覆盖用户操作。

### 点击链接优先打开桌面版

`0.12.0` 起，课程工具返回的 `play_url` 使用
`/open/review/<video_id>?start_ms=<毫秒>&library_id=<视频库身份>`。
Agent 原样引用工具链接，不自行拼接 `/review/` 网页地址。
查询字幕、看图及链接预览不会打开窗口；用户点击链接后，本地唤起页在可见时
请求桌面导航，复用已有窗口，桌面尚未启动时沿用现有入口启动。
视频库身份、视频文件和起始时间通过校验后，才把原来的 `/review/` 地址交给桌面。

正常情况下不打开网页复习页。桌面打开失败时显示原因，并提供“重试打开桌面版”
与“在网页中继续”，由用户选择，不静默切到网页。
桌面有未保存修改时先唤起原窗口，保留草稿并阻止导航。
库身份变化、视频缺失或请求失效时不提供可能指向错误视频的网页备用链接。
多个打开请求通过本机文件锁互斥，正在打开时不排队执行另一个旧定位。

链接仍是普通 HTTP 地址，会短暂经过浏览器中的本地唤起页；本地 API 必须可访问，
不会注册 Windows 自定义协议。MCP 检索本身可通过既有机制启动本地 API；
如果应用和服务都已退出，旧 HTTP 链接不能独立完成冷启动。
`open_video` 则直接请求桌面导航，不经过浏览器；返回的 `play_url` 仍保留可点击入口。
旧 `/review/` 地址继续作为网页路径保留。回执仅表示桌面接受导航，实际播放器定位另行验证。

任务写入既有 `processing_jobs`：纯转写为 `course_transcribe`，
完整批处理为原有 `batch_video_process`，顺序任务为 `course_sequence`。
MCP 可查询、取消和重试界面创建的完整批次。
纯转写重复提交相同活动目标返回原任务，完整批处理按 `request_id` 复用；
其他任务冲突继续遵循应用原有互斥规则。
任务队列中的视频受文件变更保护，不因尚未轮到该视频而允许移动或改名。

工具输入使用对象 schema、排斥未知字段并校验互斥目标；普通数据输出同时提供
`structuredContent` 和兼容文本，声明 `outputSchema`。`read_slide` 与
`read_video_frame` 仅使用 `content` 返回文字与原生图像，不声明要求结构化结果的
`outputSchema`，避免 Codex 优先读取结构化元数据而丢弃图像。
Base64 只放入图像块，不复制到文字上下文。业务错误通过 MCP `isError` 返回。
完整批处理、重试和恢复标记为有写入影响、可能访问外部服务；
带请求标识的动作标记为幂等。预览为只读，取消不承诺即时终止。

提交基线中的旧更新助手仍会拒绝这些新增路径；新包内的校验器无法改变旧助手的解包行为。
下一次发行前需核对实际旧发行包并安排完整新包的手动升级或过渡版本。
本次没有执行发行或真实原地升级，不能将当前清单校验通过视为旧版升级通过。
