# 操作体验改进

按功能记录操作中遇到的不便、改进方式和设计考虑。

## 存储与维护

### 成功转写后清理音轨，空闲时维护缓存

2026-11-10 · 关联源码：[缓存维护](../classcue/cache_cleanup.py)、
[设置入口](../frontend/src/components/CacheCleanupSection.tsx)

**原来的不便：** 部分可恢复转写目录在成功后仍保留音轨和中间文件，
封面、搜索预览和日志也缺少统一的占用检查与清理入口。

**现在的操作：** 字幕保存成功后清理临时音频，设置中可检查分类占用并手动选择清理。
默认每周在软件空闲时维护过期缓存，可修改保留天数、图片容量上限或关闭自动维护。
执行期间能查看进度与结果；任务暂停、来源视频缺失及文件冲突时保留相关资料。
停止清理保留已删除数量和实际释放空间；更新失败留下的目录不会挤占完整备份保留名额，
中断后的部分备份仍可继续清理，旧版归属不明的备份保留。
AI 缓存、依赖下载缓存和回退备份默认不自动处理，选择时显示费用或恢复能力的影响。

**设计考虑：** 清理以已保存字幕和文件归属为依据，保留学习内容及续跑材料，
同时让可重建缓存的占用和清理代价可见。

## 视频复习

### 文件夹卡片空白处也能打开

2026-11-10 · 关联源码：[视频库](../frontend/src/App.tsx)

**原来的不便：** 整张文件夹卡片都有悬停反馈，但只有图标和名称区域能够打开，
点击卡片四周空白没有反应。

**现在的操作：** 点击文件夹卡片内的空白处同样打开文件夹，根目录与子文件夹一致。
勾选、重命名、删除、发送、书签及继续复习各自响应，拖动期间和刚结束时不误打开。
关闭窗口后仍将键盘焦点还给原来的打开按钮。

**设计考虑：** 悬停反馈和可点击范围一致，同时保留独立控件的行为与键盘入口。

### 平板离线修改回到电脑后合并

2026-11-10 · 关联源码：[学习修改同步](../classcue/study_sync.py)、
[连接窗口](../frontend/src/components/DeviceStudySync.tsx)

**原来的不便：** 课程传输只支持整包替换，平板修改 AI 重点后再接电脑，
无法同时保留电脑其他视频的更新，平板也没有考题同步入口。

**现在的操作：** 首次关联后，两端通过 USB 交换考点和视频考题的新增、编辑、
移除及恢复。接收预览显示修改数量，同字段冲突并列展示电脑与平板内容，逐条选择。
保存失败保留选择以便重试，接收回执确认后才显示完成。

**设计考虑：** 同步学习记录而非覆盖整个课程；保留媒体复用、明确冲突选择和可恢复删除。
真实 MTP 验收使用两段合成课程，保护个人课程。

### 删除视频进入 Windows 回收站

2026-11-10 · 关联源码：[视频库删除](../classcue/video_store.py)、
[Windows 回收](../classcue/windows_recycle.py)

**原来的不便：** 删除只把文件搬到视频库中的隐藏目录，界面没有清空入口，
用户清空 Windows 回收站也不能释放这些文件占用的空间。

**现在的操作：** 新删除的视频和相关音频、PPT、题图归集为一个带名称的
ClassCue 文件夹并移入 Windows 回收站。确认提示明确清空后的不可恢复性；
清空前仍可使用应用内撤销和重做。Windows 中直接还原后，回到应用撤销可恢复登记。
无法回收时保留原文件并提示失败，已有历史回收记录继续可恢复。

**设计考虑：** 系统回收站负责最终空间回收，应用保留恢复字幕、学习状态等所需的
数据库快照。正常删除不保留另一份媒体副本；事务失败时才保留必要的恢复材料。

### 视频导入共用复制与移动设置

2026-11-09 · 关联源码：[统一入库](../classcue/video_library.py)、
[桌面拖入](../frontend/src/components/LibraryFileImport.tsx)

**原来的不便：** 单视频和目录批量遵循删除来源设置，拖入与副视角却始终保留，
旧命令行只引用外部路径。同样是导入，磁盘占用和来源保留结果不同。

**现在的操作：** “本机视频导入方式”统一选择复制或移动，桌面拖入、多文件、
副视角和旧入口都归档到视频库。新安装默认复制，已有偏好继续保留。
重复内容复用原记录并保留来源；浏览器上传和 USB 接收保留原端文件。
设置页直接并列展示复制、移动两个单选项及各自的来源文件处理方式，无需展开下拉菜单。
每个选项用小圆角矩形框标出可点击范围，当前选项使用绿色边框、浅绿底色和加粗底边，
悬停时显示反馈，并预留相同空间避免切换时布局跳动。

**设计考虑：** 原视频属于持久资料。移动必须等副本校验和登记、必要关联保存成功，
失败时保留来源；命令行按来源归属找回已归档视频，原目录变空后仍可续跑。

### 直接选择桌面关闭行为

2026-11-09 · 关联源码：[桌面设置](../frontend/src/components/DesktopSettings.tsx)

**原来的不便：** 关闭行为藏在下拉框中，查看其他选择和修改都需要展开。

**现在的操作：** 每次询问、最小化到托盘及退出应用直接并列显示，
选项用小圆角矩形框标出可点击范围，当前保存的选项以单选圆点、绿色边框和浅绿底色共同标明；
保存失败保留原选择。
托盘不可用时，仅禁用最小化选项。

### 先选讨论工具，再修改对应设置

2026-11-09 · 关联源码：[讨论工具设置](../frontend/src/components/DiscussionSettings.tsx)

**原来的不便：** DSH 和 Codex 分别占一个设置入口，默认讨论工具却藏在 Codex 页内，
用户难以判断应修改哪一页。

**现在的操作：** 侧栏只保留“讨论工具”，直接在 DSH 和 Codex 中二选一，
随后只显示所选工具的工作区与连接设置；选择会记住，另一工具的已保存配置保留。
目录选择或保存期间暂时锁定工具切换，旧设置链接继续打开统一页面。
工具选项同样使用小圆角矩形边框，整个区域都可点击，选中时显示绿色边框与底色。

### 设置分类之间切换不打断编辑

2026-11-09 · 关联源码：[未保存保护](../frontend/src/components/UnsavedChanges.tsx)、
[设置页](../frontend/src/pages/SettingsPage.tsx)

**原来的不便：** 从存储切换到 ASR 等设置分类也会弹出离开确认，连续配置多个项目被反复打断。

**现在的操作：** 分类之间自由切换并保留草稿，离开整个设置页时统一保存或放弃。
保存遇到必需的迁移确认或校验错误时，可返回对应分类处理；退出应用仍有未保存保护。
应用数据迁移重启前也会处理其他分类草稿；保存或放弃后重新检查迁移范围，
再次确认重启，避免配置修改使旧迁移计划失效。

### 删除召回方案后从设置页隐藏

2026-11-09 · 关联源码：[方案管理](../frontend/src/components/RecallSchemeSettings.tsx)

**原来的不便：** 删除图标实际称为“停用”，停用后的方案仍在折叠列表中列出名称，
容易让用户误以为删除未生效。

**现在的操作：** 统一使用“删除方案”，确认后从设置列表移除，也不再显示“已停用方案”区域。
删除只影响后续方案选择，历史提取结果及其方案身份继续保留。

### 用系统选择器修改存储目录

2026-11-09 · 关联源码：[存储目录](../frontend/src/components/StorageDirectoriesSection.tsx)、
[应用数据](../frontend/src/components/ApplicationDataSection.tsx)

**原来的不便：** 目录框允许手动填写地址，容易输错，也与旁边的文件夹选择按钮重复。

**现在的操作：** 视频音频、ASR、日志及应用数据目录均通过系统文件夹选择器修改，
路径改为不可聚焦的静态展示，不显示输入光标或输入框聚焦效果，仍可选中文字复制；
取消选择保留原目录，保存与迁移确认流程继续保留。

### 在 Codex 中检索课程并核对原话

2026-11-08 · 关联源码：[课程工具](../classcue/course_tools.py)、
[学习 Skill](../integrations/codex-desktop/skills/classcue-courses/SKILL.md)

**原来的不便：** 忘记讲解位置时，需要逐个尝试搜索词、打开视频并翻阅附近字幕。

**现在的操作：** Codex 通过课程工具寻找候选、换词检索、读取前后文，
回答附视频与时间链接；用户要求观看时才唤起桌面。
课程或普通文件夹均可作为范围，不为检索额外建立课程绑定。

**设计考虑：** 工具返回证据而不内置第二套问答模型；字幕缺失与无匹配分开说明。
批量转写只补缺失字幕，跳过已有结果，进度和取消由后台任务管理。
桌面任务中心显示“课程转写”、实际模型和逐项进度；重启后的未完成项显示为待转写，
空字幕结果明确提示检查语音，不再显示为已成功转写。
需要考点分析或题目提取时，Agent 可预览并提交已有完整批处理，
查询、取消、重试或恢复界面和 MCP 创建的批次，不再要求用户手动打开处理页。
预览说明 AI 调用、目录归档及重新转写影响，避免将“补字幕”扩大为完整分析。
2026-11-09 起，APP 与 MCP 共用视频库内保存的召回选择，预览可核对来源与版本；
“ASR 后提取 PPT”可一次提交为本地顺序任务，失败或取消时停止后续步骤，
聊天结束后仍由 APP 后台执行，任务中心展示各步骤状态。
`0.7.0` 补齐指定时段 PPT、实际画面和已有考点题目读取，
可按视频查词、合并相邻命中并读有限上下文；换聊天后可找回任务 ID。
图片真正作为图像返回，搜索摘要和模型分析仍与原始字幕证据区分。
`0.8.0` 将插件作为同仓库的可选配套分发，安装无需 npm，
APP 首次保存 Codex 设置即可创建连接；已有讨论与课程工具共用连接。
安装、更新及个人来源迁移见[可选配套说明](features/codex-plugin-install.md)。
真实调用及 ASR 环境验证边界见[验收记录](validation/codex-course-tools-validation.md)。

2026-11-10，`0.9.0` 新增 `search_bookmarks`：用户说“我记得有个视频讲解了自注意力”，
Agent 可先搜索自己写过的书签提醒，直接找回视频、原时间点和播放链接，再读取附近字幕。
书签与 APP 共用原数据，修改、删除和视频移动后立即反映；
没有时间点的提醒保留为整段视频，不推测讲解位置，用户备注与教师原话分别说明。

2026-11-10，`0.10.0` 将名称目录、书签、字幕和考点题目统一到 `search_library`。
Agent 无需先猜资料类型，可以用同义候选组与跨句时间窗找到讲解，再按原证据核对。
同一位置多来源汇合、结果按词覆盖与紧凑程度排序，控制重复视频占据首页；
缺少时间仍只确定视频，候选截断时明确要求收紧范围，翻页检查资料是否变化。

同日 `0.11.0` 增加按需字幕同音候选：正常无结果时自动后备，
用户提示 ASR 错字时可主动启用，明确“B包”时直接与“闭包”同组检索。
无需维护课程术语表；返回原字幕及待核实的发音原因，Agent 再读上下文确认。
首次只为当前范围建立本地缓存，后续复用；索引未完成时明确说明，避免空结果误导。
课程 Skill 同时明确按任务主动核实：读字幕后发现术语歧义、画面指代、
公式代码缺失或候选冲突时，Agent 自行查看相应 PPT／视频帧，
比较更切题的讲解并附证据；文字证据足够时停止补查。

同日 `0.12.0` 修复 PPT 和视频帧调用成功但 Agent 只收到类型、尺寸的情况：
图片通过原生图像块进入模型上下文，避免被重复附带的结构化元数据覆盖。
已有 PPT 不需重新提取；已安装插件需更新并重新加载服务后使用。

2026-11-10，`0.12.0` 将 Agent 给出的回放链接改为桌面优先入口。
点击后短暂经过本地唤起页，播放交给已有桌面窗口；打不开时才提供明确的网页备用入口。
桌面有未保存内容时只唤起窗口，不跳走或丢弃草稿；查询和链接预览不抢焦点。
链接仍依赖运行中的本地 API，服务完全退出后需先打开 ClassCue，或由 MCP 查询启动服务。

### 按课堂片段发起讲解

2026-11-07 · 关联源码：[片段讲解](../frontend/src/components/CodexVideoClip.tsx)、
[片段快照](../classcue/codex_video_clip.py)

**原来的不便：** 没听懂教师配合 PPT 的讲解时，需要手动寻找、复制对应字幕，
再逐张选图，容易漏掉原话或混入后面才出现的内容。

**现在的操作：** 在播放器下方点击“讲解片段”，直接拖动原播放器进度条上的
起止手柄选取时间，拖动时同步定位画面，时间以只读读数显示，无需手动填写。
选好后点击“预览片段”自动读取教师原话和精选 PPT；
点击“调整片段”可返回进度条重新选取。取消不需要的图片，再准备 Codex 草稿。
用户在 Codex 中补充问题、编辑文字和删减图片，最后自行发送；片段讨论可以再次打开。

**设计考虑：** 保留字幕与图片的时间对应关系，让用户明确知道带入了什么。
字幕边界保留完整句子，图片只取范围内实际出现的精选状态；
没有图片时允许只问字幕，资料不全时不代替用户启动提取。
预览、准备草稿、打开讨论和重新追加分别显示进度；图片读取失败会标明具体图片，
取消该图后仍可继续。历史记录显示编号、图片数量和创建时间，打开历史不影响当前
片段的准备。已粘贴的草稿可在检查 Codex 后明确重新追加，也可新建独立讨论。

2026-11-09 补充：选段沿用主视频时间轴，起止手柄不能交叉，支持键盘微调；
重新调整范围后读取新预览，不沿用旧范围的字幕、选图或草稿成功状态。

2026-11-10 补充：准备草稿时先等待 Codex 目标就绪及键鼠短暂静止，
点击后的松开或导航期间的鼠标移动不再立即取消整次传入。
粘贴开始后的其他操作仍会停止传入；持续操作超时会提示松开按键后重试。

### 视频与资料共用标签栏

2026-11-08 · 关联源码：[标签栏](../frontend/src/components/ReviewTabs.tsx)

**原来的不便：** 顶部标签栏只能保留打开的视频，看资料后回到视频，
再找原资料需要重新进入课程。逐份资料增加标签后，又容易挤满标签栏。

**现在的操作：** 顶部只保留一个“学习资料”标签，课程列表、上传资料和视频例题
都在其中切换，不再为每份文件新增标签。点击标签回到最近访问的课程、文件或视图，
继续使用已有阅读位置。视频仍分别显示。关闭当前标签进入相邻标签，关闭其他标签不跳转。
有未保存的题目时，切换或关闭仍需先保存、放弃或继续编辑。
按 `Ctrl+Tab` 向右、`Ctrl+Shift+Tab` 向左循环切换，也可使用
`Ctrl+PageUp / PageDown`。切换后高亮并显示目标标签；弹窗或录入快捷键时暂停，
快捷键设置中可查看固定按键说明。

**设计考虑：** 学习资料作为一个整体入口，减少顶部标签数量；标签身份固定，
返回地址随当前资料位置更新。不同视频库分别保留标签。

### 播放快捷键默认跟随视频

2026-11-06 · 关联提交：`85270fc`

**原来的不便：** 必须先点击视频，空格和长按右箭头才能控制播放。
用鼠标调整倍速后，方向键还可能继续改变倍速，需要再次点击视频。

**现在的操作：** 进入复习页即可用空格播放或暂停，短按右箭头前进 5 秒，
长按临时使用 3 倍速，松开恢复原倍速。鼠标选择倍速后可以继续控制视频。
输入文字、打开菜单或用 Tab 操作按钮时，按键优先服务于当前操作；
菜单里用方向键选择，确认后仍保留按钮的键盘操作。

**设计考虑：** 减少为了使用快捷键而重复点击视频，同时保留文字输入
和主动使用键盘操作控件的习惯。

### 副视角一键估算时间偏移

2026-11-06 · 关联源码：[副视角设置](../frontend/src/components/SecondaryViewControl.tsx)

**原来的不便：** 需要在两个视频之间反复试听、手动试填时间差；
副视频噪声较大时尤其难找对应位置。

**现在的操作：** 点击“自动对齐”，从主字幕长句附近查找副视频语音，
先以小预算快速检查多个长句位置，跳过过短的点名语音；
不足时自动扩大范围，复用首轮结果，累计 ASR 音频最多 15 分钟。
两处对应一致则保存，单处强匹配提供候选；
噪声或冲突证据不自动改偏移。前面有任务时自动排队，支持取消和撤销。
开始后可以关闭设置继续观看，完成时播放器自动更新偏移；切换音频来源也保留
任务进度和取消入口。
撤销使用折返箭头和文字按钮，操作键带底色与边框；音频选项悬停时使用弹层自身
的配色，保持文字清晰。

**设计考虑：** 用已有字幕缩小查找范围，让程序承担重复比对；
证据不足时保留人工判断和原设置。
2026-11-07 补充：不同位置轮流分配识别额度，避免开场点名用完全部预算。
显示所用模型、识别音频时长、兜底阶段和停止原因，便于判断是否需要人工调整。
2026-11-09 补充：“设置 → 存储与导入 → 副视角”可记忆“导入副视角后自动对齐”，
默认关闭。开启后，新导入成功即发起对齐，已有副视角重新打开时不重复启动。
自动对齐无法启动时保留导入结果，提示原因并允许之后手动重试。
导入中离开页面不跳过成功后的对齐；关联已被更换或偏移已修改时，拒绝旧请求启动任务。

### 副视角沿用主音频，降噪沿用最近选择

2026-11-06 · 关联源码：[播放器](../frontend/src/components/VideoPanel.tsx)、
[音频控制](../frontend/src/components/AudioChannelControl.tsx)

**原来的不便：** 切换副视角会听到副视频原声，无法继续使用主视频中更清楚的录音；
换视频后还要重新开启降噪。

**现在的操作：** 副视角设置中可勾选“使用主视频音频”，自动静音副视频原声。
主音频与字幕使用同一时间，修改偏移时一起对齐画面。降噪按最近一次主动开关的选择，
在后续视频播放时恢复；自动恢复失败保留原声。

2026-11-07 补充：副视角沿用主音频时，小幅时间差通过轻微调整音频速度逐步追齐，
避免倍速播放时频繁跳转音频造成断续。拖动进度和切换视角仍立即对齐。
播放请求被短暂中断时自动重试，持续失败才提示；主音频恢复后自动清除提示，
切回主视角也不残留旧音频错误。

**设计考虑：** 画面来源与声音来源可以分别选择，重复使用的降噪习惯自动延续，
同时保留用户主动关闭的选择。
