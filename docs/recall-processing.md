# 考点召回多选与补充识别

视频库处理选项、单视频处理页、文件夹批处理页共用召回多选控件。
默认仅勾选中召回；可同时勾选高、中、低召回，也可取消全部勾选。
点击开始处理时才校验：未选择任何方案则显示提示，不发送处理请求；
重新选择后清除该提示，允许再次提交。
界面提示每个方案独立调用 AI，多选会增加 token 用量和处理时间。

## 处理请求

原有单视频、选中视频批处理、文件夹批处理接口支持：

```json
{
  "analysis_modes": ["high_recall", "medium_recall", "low_recall"],
  "force_retranscribe": false
}
```

`analysis_modes` 去重并按请求顺序执行。空数组和未知方案返回422。
未提供此字段的旧客户端仍可使用 `analysis_mode`；两者均未提供时默认中召回。
保留旧版 `strict_exam_intent` 单方案请求和旧界面参数的兼容行为。
前端同时提交首选 `analysis_mode`，以保留旧接口字段。

单视频各方案复用已保存字幕；主动勾选重新转写时，仅第一个方案重新转写。
批处理每个视频仅准备一次字幕，再依次执行所选召回方案。
每完成一个方案，就在该批处理条目的 `completed_modes` 中保存断点。
API异常后重试同一批处理时，跳过已经完成的方案。
任务响应通过 `analysis_modes` 返回其包含的方案，供前端恢复任务状态。

## 复习页补充识别

复习页仍以单个召回方案为一个阅读视图。当前方案没有任何考点时，
读取 `/api/videos/{video_id}/analysis-runs` 判断是否真正完成过识别：

- 无完成记录：显示“识别高/中/低召回”按钮。
- 完成但考点为零：显示已完成和无考点说明，不再次提供启动按钮。
- 已有考点仅因查看筛选或移除而不可见：沿用筛选空态，不认为尚未识别。
- 读取状态失败：显示错误和重新读取入口，不推断为尚未识别。
- 运行中：恢复对应任务、显示进度，阻止重复提交。
- 失败或中断：允许重试；提交错误也保留重新提交入口。

用户点击按钮后调用：

```http
POST /api/videos/{video_id}/analysis
Content-Type: application/json

{"analysis_mode": "high_recall"}
```

该接口仅使用已保存的字幕，快照当前 AI 连接，创建 `video_analysis` 任务。
其他任务运行时自动加入同一个串行队列，前面的任务结束后开始；
排队期间不创建模型、不发送 AI 请求。排队与运行状态均保存在任务记录中，
刷新后通过 `/api/videos/{video_id}/processing-options` 的 `active_jobs` 恢复当前方案任务。
缺少字幕、已经完成该方案、同视频同方案重复提交，或视频已被完整处理任务占用时返回409。
资源暂停任务需先继续或停止；迁移与更新期间仍不接受新任务。
不触发ASR、不移动视频文件夹，也不替换其他方案的考点及其复习状态。
完成后前端刷新考点与完成记录，保持播放器实例、播放位置和当前阅读方案。
仅切换方案或读取状态不会调用模型；补充识别按钮旁明确提示额外 token 用量。

## 单选排队与召回切换

视频库和单视频处理页提交 `/api/videos/{video_id}/process` 时，
其他任务运行不会拒绝新视频，而是按提交顺序排队。
视频库单选按钮显示“加入处理队列”，提交后清除选择并显示等待提示。
同一视频已有排队、运行或资源暂停任务时，不允许再发起完整处理；
排队视频也受重命名、删除等任务保护。等待任务可在任务详情中单独停止，
不会启动它的模型调用或修改其他视频的结果；前一任务失败后继续处理后面的任务。
批处理入口仍沿用原有互斥规则，运行任务期间需单选视频追加。
前项因资源不足暂停时，已提交的后续任务保持等待；继续时优先续跑暂停项，
完成后再按原提交顺序处理后续任务。停止暂停项也会释放等待队列。
任务详情地址保留 `jobId`，切换同视频的不同任务后，停止和继续均作用于所选任务。
桌面选择“停止任务并退出”时，通过 `/api/jobs/stop-all` 原子阻止新任务并停止整队，
等待运行任务安全保存后关闭服务；目录迁移和更新准备期间拒绝该操作。
关闭或重启服务沿用原有中断恢复，不会在重启后自动调用 AI。

复习侧栏的“默认召回”和多方案“自定义召回”各有两个独立入口：
点击方案名称直接切回该组上次选择的方案，右侧箭头只展开或收起方案列表。
初次默认直达中召回，列表保留方向键、Home/End 切换，Esc 收起并回到展开按钮。
悬停提示区分切换和展开，当前选择继续显示选中状态，长方案名称允许换行。

## 验证

- 后端：`tests/test_recall_analysis.py` 和 `tests/test_web_batch.py` 覆盖追加识别、
  其他方案与文件夹归属保持、零结果、失败重试、防重复、单选串行排队、
  取消等待任务、前项失败后继续，以及模式级断点。
- 队列与退出：`test_job_queue_controls.py`、`test_qwen_resource_integration.py`、
  `test_desktop_runtime.py` 覆盖资源暂停、续跑优先、队列顺序、整队安全停止和迁移保护。
- 前端：`App.recall.test.tsx` 覆盖播放位置保持、结果刷新、空结果与筛选区分、
  错误恢复及刷新后恢复运行中的任务；`RecallModeControl.test.tsx` 覆盖多选和取消全部勾选。
- 浏览器：`node tests/frontend_recall.cjs` 使用内存API响应核验交互与响应式布局，
  只读复用本地视频用于播放检查，不调用真实AI。
