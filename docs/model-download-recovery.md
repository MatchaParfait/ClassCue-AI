# 模型下载暂停、恢复与临时文件清理

实施日期：2026-10-16。覆盖 Whisper turbo、Whisper large-v3、Qwen、FireRed、Paraformer 和 Dolphin；Nano 底层兼容路径沿用相同状态记录。

## 用户操作

- 设置页模型卡片和模型任务抽屉提供“暂停下载”。请求发出后显示“正在暂停”，等传输停止、续传记录保存完毕后才确认“下载已暂停”。
- 暂停或异常退出后显示“继续下载”“清理未完成下载”，以及已保留数据量和已完成文件大小。
- 刷新页面或重启服务后恢复未完成状态，不自动发起下载。继续操作沿用暂停前的 CPU / GPU 设备选择。
- 清理只删除模型目录内的 `.part`、对应的 aria2 控制文件与下载身份记录、Hub `.incomplete` 文件、待验证的临时清单。完整权重、就绪清单、Hub 完整缓存和推理环境保持不变。
- 如果保留了完整权重，清理临时文件后仍可继续准备；没有临时文件时清理按钮禁用。如果只有空的暂停记录，允许清除记录。
- 模型已经就绪但存在旧下载源遗留的临时文件时，只提示清理，不误报为需要继续下载。
- 完整删除仍使用原有“清理模型缓存”，两种清理有独立接口。

环境安装和最终就绪提交阶段不可暂停下载，按钮禁用并说明原因。下载、文件清单获取和校验阶段可请求暂停；如果当前正在等待网络响应，会等响应结束或网络超时后安全退出，不会提前显示成已暂停。任务原有“停止任务”操作仍保留。

## 数据与恢复

`classcue/model_downloads.py` 在应用管理的各模型目录内原子写入 `.preparation-state.json`，保留设备、阶段、当前文件和接收字节量。正常完成后移除；上次状态为准备中、但不存在运行任务时解释为异常中断。

原有任务状态保持兼容：主动暂停使用 `status=interrupted`、`stage=download_paused`；保存续传记录时使用 `stage=pausing`。前端据此显示暂停状态，不弹出任务失败错误。

新增接口：

| 接口 | 用途 |
| --- | --- |
| `POST /api/jobs/{job_id}/download/pause` | 请求独立模型准备任务安全暂停 |
| `POST /api/asr/models/{model_id}/download/resume` | 沿用原设备创建新的继续任务 |
| `DELETE /api/asr/models/{model_id}/download/incomplete` | 创建仅清理未完成文件的任务 |

模型快照新增 `download_state`；任务返回关联的 `model_id`。运行中的准备、删除和临时文件清理互斥，跨进程沿用模型操作锁。符号链接和目录联接逃逸会在任何清理动作前被拒绝。

aria2 每秒保存分段记录。暂停先调用 `forcePauseAll` 停止传输，再关闭下载器以保留记录；意外进程退出后使用已保存的记录继续。Windows 下下载器从挂起状态加入独立的 kill-on-close Job，后端进程被强制结束时下载器也随之退出，避免重启后两个进程同时写缓存。顺序 HTTP 下载使用 Range；服务器忽略 Range 时重新下载该文件。下载身份改变，或分段记录丢失且文件未完整校验时，舍弃不安全的临时文件。继续后仍需大小和 SHA-256 校验。

Hub 备用源保留 SDK 的未完成文件与下载元数据，继续使用固定提交和文件身份下载；暂停信号跨工作线程传播，被原生传输层包装时重新检查，避免误触发换源。

分段下载和 Hub/Xet 可能预分配文件，恢复界面不把文件长度当作已接收字节量；无法完整确认时显示“确认保留至少”，使用最近已确认的接收量。进度条和剩余时间重新采样，不沿用暂停前的下载速度。
