# DSH 默认根目录与课程资料工作区树

日期：2026-10-30。

状态：默认根目录配置、课程／资料原生工作区树和逐题会话已实现。
ClassCue 插件为 `0.4.1`，适配 Windows 桌面 DSH `0.2.1-rc.5`。
本文记录已落地的工作区组织规则；桥接机制及验收命令见
[单题 DSH 桌面桥接](dsh-desktop-bridge.md)，整体学习方向见
[资料题目与 DSH 学习记录开发计划](material-question-study-plan.md)。

## 目标形态

用户只在 ClassCue App 中选择一次默认 DSH 工作区根目录，
例如 `classcue-AI-DSH`。之后从题目发起讨论时，程序自动维护以下层级：

```text
classcue-AI-DSH/                         默认根目录
├─ 数据库概论/                          课程目录
│  ├─ 2024年数据库春季试卷/             资料文件目录
│  │  ├─ 第1题 · 关系代数               DSH 独立会话
│  │  ├─ 第2题 · 候选码                 DSH 独立会话
│  │  └─ 第3题 · 数据库设计             DSH 独立会话
│  └─ 2023年数据库秋季试卷/
│     ├─ 第1题                          DSH 独立会话
│     └─ 第2题                          DSH 独立会话
└─ 算法设计与分析/
   └─ 模拟试卷/
      ├─ 第1题                          DSH 独立会话
      └─ 第2题                          DSH 独立会话
```

会话是 DSH 管理的上下文记录。上述树只表达归属，
不表示把每个会话导出成同名磁盘文件或同名文件夹。
课程及资料目录使用人类可读的名称。

用户在 DSH 中选择“按工作区树”，查看原生树结构即可。
插件负责构建、登记和维护对应关系，不重新实现侧栏、分组菜单或聊天界面，
也不强制修改用户当前的 DSH 分组显示偏好。

## 用户操作流程

### 首次配置

1. 用户进入 ClassCue“设置 → DSH 讨论”，点击“选择默认工作区”，
   在 App 原生目录选择器中选定根目录；无需先创建课程或题目。
2. App 记住该根目录，以及其对应的 DSH 实例身份。
3. 后续课程和资料使用这个根目录，不再要求每门课、每份试卷分别选择工作区。

题目旁的“DSH 桌面连接”是同一配置的快捷入口，和全局设置共享保存结果。
此目录只管理由 ClassCue 发起的题目讨论，不改变用户在 DSH 内独立创建的其他讨论。
新讨论无需在 DSH 中选择地址；旧版尚未完成工作区选择的请求仍保留原意，
用户可完成原选择，或明确新建独立讨论以使用新目录结构。

根目录设置与插件连接文件是两件事。普通安装继续沿用自动连接能力，
不能要求用户为了设置根目录去寻找 `connection.json` 等插件内部文件。
目录选择操作放在 App 中；连接、目录和工作区能力通过现有桥接协调。

### 从一道题进入讨论

1. 用户打开某门课程的一份资料，框选并保存一道完整题目。
2. 点击统一命名的“在 DSH 中讨论”。
3. 插件读取题目已保存的课程、资料文件、题目及内容版本身份。
4. 在默认根目录下创建或复用课程目录。
5. 在该课程目录下创建或复用这份资料的目录。
6. 在该资料对应的 DSH 原生节点下，创建或打开这道题的会话。
7. 首次创建会话时，将题目文字和题图传入该会话，打开 DSH 对应上下文。

目录按需建立：首次从这份资料发起 DSH 讨论时才创建所需层级。
仅在 App 中阅读或导入资料，不要求 DSH 同时运行，也不提前批量创建空会话。
默认 profile 沿用已有桌面唤起行为；连接失败时保留本地题目，可重试。

### 后续使用

- 同一资料内的另一道题：复用课程目录及资料目录，新建该题的独立会话。
- 同一课程的另一份资料：复用课程目录，建立另一份资料目录。
- 另一门课程：在同一默认根目录下建立另一个课程目录。
- 再次点击同一道题：回到原会话及其已有上下文，不重复创建会话或插入题图。
- 用户在 App 选择“新建独立讨论”时，为同一道题增加另一会话，旧讨论保留。
- 用户在 DSH 使用原生分支时，插件按父会话身份自动关联到同一道题及其原内容版本，
  无需回到 App 新建；分支的分支也可同步。App 讨论列表保留并标明父子关系。
- 讨论记录只显示 DSH 实际开始过且未归档的会话；未发送草稿保留恢复能力但不计数，
  已归档、已删除或归属失效的会话同步隐藏，取消归档可重新显示。
- 一道情景题包含多个小问时，小问仍属于同一道题、同一上下文。

按钮始终显示“在 DSH 中讨论”，不因已有会话改成“继续 DSH 讨论”。
首次创建和后续回访由已保存的绑定关系判断，不让用户承担不同入口的选择。

## 题目传输边界

- PDF、照片和视频例题使用已保存的题图；PDF 裁片从原页面生成。
- 同一道题有多个选区时，多张题图按来源顺序传入同一会话。
- Markdown 传入选定的原文文字，存在补充题图时一同传入。
- 图片题只传题图，Markdown 只传选中的原题文字及补图；
  课程、资料名、题号和来源保留为绑定元数据，不插入草稿正文。
  不传整份试卷或无关课堂字幕。
- 本文的“发送题图”指自动传入对应 DSH 会话的草稿，
  沿用用户在 DSH 确认并发送模型请求的方式；不将目录自动创建等同于模型自动调用。
- 已有会话再次打开只导航，不覆盖用户正在编辑的草稿。

模型选择、消息提交、解题、工具调用和上下文管理继续由 DeepSeek Harness 负责。
本轮不实现自动总结或题目学习记录，学习记录是后续独立阶段。

## 层级与身份映射

名称负责展示，稳定 ID 负责识别。禁止仅靠课程名、文件名或路径字符串查找原对话。

| 层级 | 绑定依据 | 维护内容 |
| --- | --- | --- |
| 默认根目录 | App 库身份、DSH 实例、根目录配置身份 | 用户选择的位置及连接归属 |
| 课程目录 | 根目录配置身份、课程 ID | 课程显示名、受管理目录位置、所需原生节点身份 |
| 资料文件目录 | 课程绑定、资料 ID | 资料显示名、子目录位置、会话所属原生工作区或分组身份 |
| 单题会话 | 资料绑定、题目 ID、题目内容版本 | 请求 ID、DSH 会话 ID、草稿及回执状态 |

当前已有 `course_id`、`document_id`、`question_id`、题目版本和持久请求记录，
应复用这些身份，不重新按题干、文件哈希或名称生成另一套题目身份。
根目录、课程目录和资料目录的具体表结构与桥接字段在实现时定稿。
不得直接读写 DSH 私有数据库来伪造目录或会话记录。

## 命名与维护规则

- 课程目录初始使用课程名称，资料目录初始使用文件显示名的主名称；
  例如 `2024年数据库春季试卷.md` 对应 `2024年数据库春季试卷`。
- Windows 不允许的路径字符由程序处理，不要求用户为正常导入资料手动改名。
- 不同资料即使同名，也保留各自身份；冲突时添加简短可读序号，不合并文件或会话。
- 断线、超时、重启和重复点击复用同一创建请求及已登记节点。
  不能留下重复的课程目录、资料目录或题目会话。
- 名称变化不改变稳定身份，不因改名重新创建整套目录或会话。
  原生重命名及路径迁移能力未验证前，保留已绑定位置，不自动搬移历史会话。
- 更换默认根目录只影响尚未建立目录绑定的资料。
  已绑定资料及其新增题目继续复用原资料目录；历史搬迁需要单独明确的迁移操作。
- DSH 节点或对话被外部删除、归档或移出原位置时，保留原绑定并显示具体原因。
  不静默新建一个空对话冒充原上下文。
- App 内移除资料不自动删除 DSH 历史，恢复资料后仍能使用原讨论记录。
- 题目内容修改后保留旧版本会话，新讨论明确绑定新版本。

## 与旧实现的差异

| 旧实现 | 新实现 |
| --- | --- |
| 首次讨论时，在 DSH 选择课程工作区 | 在 App 配置一次默认根目录，后续自动创建课程与资料层级 |
| 课程直接绑定一个工作区，课程各题都放入该工作区 | 默认根目录下有课程目录，课程下有资料目录，会话归属到资料节点 |
| 无资料级子目录绑定 | 每份资料保存独立目录及原生节点绑定 |
| 已有讨论时按钮改为“继续 DSH 讨论” | 入口统一为“在 DSH 中讨论” |
| 已有逐题请求、版本、恢复和草稿保护 | 保留这些机制，扩展目录归属，不重做聊天运行时 |

原先的“不同课程不能选同一工作区”校验不能直接照搬到默认根目录上。
默认根目录本来就由所有课程共用；应在根目录下按课程与资料的实际节点身份隔离，
并确保题目会话归入正确的文件级节点。

视频例题的单题传输已经存在。为了保持“来源 → 单题会话”的结构，
本轮按来源视频对应的稳定 ID 建立资料级目录，初始名称使用视频主文件名，
归于所属课程；不会将整门课程的视频题平铺回课程节点。

## 实施顺序

1. **核实原生工作区树机制。**
   使用已安装目标桌面版本的接口或源码，确认原生树是根据目录路径派生，
   还是需要登记父子节点；确认会话应绑定到哪种原生节点。
   已核实 `rc.5` 的原生树按已登记工作区的规范目录路径计算最近父节点；
   插件使用 `workspaceRegistry.create(path, title)` 登记根、课程及资料三个节点，
   通过 `sessionController.create({workspaceId, sessionId})` 将题目会话归入资料节点。
   不把仅在磁盘创建文件夹、而 DSH 树中不可见当作完成。
2. **补充默认根目录设置。**
   在 App 配置并持久保存一次根目录，处理目录取消、不可写、
   DSH 实例不匹配和连接离线，复用已有桌面连接。
3. **实现目录创建与绑定。**
   创建或复用课程、资料目录，并按原生机制注册到 DSH；
   持久保存稳定映射，支持断线和部分完成后恢复。
4. **接入单题会话。**
   将现有会话创建目标改为资料节点，保留请求幂等、题图传输、
   内容版本、原对话回访与已有草稿保护，统一按钮文案。
5. **处理已有数据。**
   旧版课程级和文档级讨论仍回到原位置，不自动迁移。
   新结构在明确升级后用于新讨论；未完成旧请求仍按原意恢复。
   插件声明 `workspace_tree`，新请求保存 `layout=workspace_tree` 及 `root_id`；
   App 在首次创建及恢复时检查该能力，避免旧插件将题目平铺到课程节点。
6. **同步文档并验收。**
   更新桥接协议、使用说明和开发计划的实际状态，
   完成代码审核、合成测试及隔离桌面工作区树验收。

## 验收标准

- App 只需设置一次根目录；两门课程、每门两份试卷、每份多道题，
  均自动归入正确层级，不要求逐课程或逐试卷再次选择目录。
- 用户切换到 DSH“按工作区树”后，可看到课程与资料层级，
  题目会话实际属于对应资料节点，不是 App 内单方面显示的目录。
- 首次点击创建会话并准备题图；重复点击、超时重试和两端重启后打开同一会话。
- 不同题目具有独立上下文，完整情景题的小问保持同一上下文。
- 同名资料、不同格式同名文件、改名和题目内容版本变化不会串会话。
- 创建课程、创建资料节点、创建会话任一阶段失败，可恢复已完成部分，
  不丢原题、不重复生成目录，不触发模型请求。
- 根目录取消、权限不足、DSH 离线、旧插件、会话被删及旧记录恢复有明确结果。
- PDF 裁片、Markdown 原文及多图顺序正确；不会覆盖已有草稿。
- 自动测试使用临时目录、合成资料和假原生适配器；
  桌面验证使用隔离实例，记录“工作区树实际可见”和“会话归属准确”的证据。
- 原生未发送会话仍按 DSH 自身的空白会话规则显示，侧栏可能只显示当前空白会话；
  App 保留每题独立绑定和草稿，模型发送后由 DSH 显示普通历史记录。
  插件不发送虚假用户消息来改变侧栏显示。

## 实现与验证入口

- App 的“设置 → DSH 讨论”及题目旁的“DSH 桌面连接”共用默认工作区目录选择，保存到库内的
  `dsh_bridge_roots` 和 `dsh_bridge_root_selection`；选择被取消或保存失败时保留旧选择。
  连接文件手动选择收在“自定义 DSH profile”中。
- Host 在自身状态中保存 `roots`、`tree_courses`、`tree_documents`；
  旧 `courses`、`documents` 仅用于恢复旧讨论，历史不会自动搬迁。
- 目录命名先处理 Windows 非法字符、设备保留名、尾部点与空格，
  同名冲突使用 `(1)` 等序号。创建前保存路径意图，登记失败后按原路径重试。
- `PUT /api/dsh-bridge/workspace-root` 接受 `path` 与当前 `instance_id`；
  `GET` 同一路径返回本实例已保存的默认目录，可离线读取。
- 自动化与隔离桌面脚本见
  [单题 DSH 桌面桥接](dsh-desktop-bridge.md#验证)。
  根目录原生选择器的取消由前端测试覆盖；真实模型发送与学习记录仍不在本轮范围内。
