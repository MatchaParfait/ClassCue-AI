# 考点检索 Harness 完整设计

> 状态：双阶段控制器、字幕证据模块、接口及面板已实施，并进行定向合成验证。
> 正式客户端已验证搜索、分 P 目录及登录态字幕读取；所选模型的端到端判断效果尚未验证。
> 本文扩展现有首版方案；首版实现和第三方许可说明见
> [考点驱动的 B 站检索与字幕核验](bilibili-study.md)。

## 1. 总体架构

将当前固定流水线改为**由程序控制、LLM 提供结构化判断的有界检索闭环**。
不引入 DSH，不绑定 DeepSeek，继续复用 ClassCue 的模型连接、后台任务和 SQLite。

```text
明确目标与匹配标准
  → 生成并确认搜索方案
  → 精确知识点搜索与建立候选队列
  → 初筛、读取字幕、提取证据、综合核验
  → 达标：交付结果
  → 未达标：课程类别搜索，按实际结构选择单视频、分 P 或合集章节
  → 达到边界：解释原因并停止
```

拆分为目标规划器、候选管理器、字幕读取器、证据提取器、综合核验器、
调度控制器和运行记录七部分。LLM 不直接访问网络、决定权限或增加预算；
所有动作由程序校验后执行。

## 2. 先建立可核验的匹配标准

- 规划阶段同时生成“目标卡”和搜索词。目标卡包含核心知识点、期望讲解深度、
  已知题型或解法、用户明确限制，以及尚不确定的内容。
- 每个要求记录来源：课堂字幕编号或用户补充字段。没有证据的题干、条件、
  方法不得补造；术语无法确定时请求用户澄清，不带着猜测进入检索。
- 用户可以修改并确认目标卡。核心要求、补充要求和明确排除条件分别保存，
  后续不能为了接受某个视频而自动放宽核心要求。
- 讲解深度分为“概念解释”“方法讲解”“例题应用”。默认采用材料能支持的目标；
  没有具体题目时，不建立“原题相同”要求。
- 对每个要求逐项判断：未发现、仅提及、实际解释、例题应用、存在冲突或证据不足。
  **不采用模型自报的匹配百分比作为通过条件。**
- “覆盖目标考点”要求全部核心项达到指定深度、没有明确限制冲突，并具有有效
  字幕证据；部分核心项得到支持则为“部分相关”，其余进入不相关或证据不足。

## 3. 候选队列与搜索反馈闭环

精确知识点搜索优先，找到一个满足目标、具备字幕证据的讲解即结束。
精确阶段候选耗尽或用完阶段额度仍未达标时，再执行用户确认过的课程类别搜索。
课程搜索同样支持普通单视频；分 P 和合集均为可选结构，不是课程检索的前提。
最多三轮：精确搜索、课程搜索、必要时补充课程搜索。第三轮新词默认等待确认。
认证、风控及模型故障暂停任务，不当作“知识点没有命中”触发扩大搜索。

- 所有结果按 BV 去重，保留来自哪些搜索词、哪一轮、原始排序和元数据；
  分 P 按 BV、CID 建立独立取证单元，不因重复命中重复读取。
- 元数据初筛输出优先级、入选或排除理由、可能覆盖的要求及不确定项。
  模型只能引用现有候选 ID；没有明确排除依据的候选保留在待选队列。
- 标题、简介和课程目录只能决定取证顺序，不能证明考点覆盖。合集章节和多 P 标题用于选择取证单元；
  执行每视频限制时从队列补足，不再简单丢弃超额项后结束。
- 先读取高优先级候选。无字幕、读取失败或核验不相关时，自动选择队列中的
  下一项，不重新从头搜索，也不把这些失败计为已核验推荐。
- 现有候选不足时，由控制器分类原因：搜索过窄、术语歧义、学段不符、
  仅有概念材料、缺少目标方法或字幕不可用；再决定是否需要新搜索词。
- 改写只能针对缺失要求，允许术语同义表达、去掉非必要限定或改搜方法专题；
  禁止改变用户明确限制、编造条件，或重复执行已经完成的相同查询。
- 每轮结束比较新增候选、可用字幕和新增证据。没有任何新增候选或证据的
  完整扩展轮后停止，避免无效循环。
- 首次确认增加“允许在本考点目标内自动调整搜索词”选项，默认关闭。
  未授权时，新搜索词进入待确认状态；用户确认前不得发送到 B 站。

### 3.1 课程目录导航与章节定位

搜索命中一门系统课程时，先读取可用目录，再决定读取哪些章节的字幕。
目录导航是候选管理器的职责，不能只处理搜索结果默认播放的第一课。

- 明确区分跨 BV 的合集、合集中的视频及同一 BV 内的分 P。平台返回什么层级就
  保存什么层级，允许没有合集或没有分 P；不得仅凭页面缩进或名称推断身份。
- 目录节点保存来源入口、可用的合集及章节标识、标题、顺序、时长和父子关系；
  最终取证单元必须解析到真实 BV、CID 和分 P 序号。未知标识先待解析，不能猜测。
- 读取搜索命中视频所属的直接课程目录；不扩展作者全部投稿，也不递归遍历其他合集。
  同一合集被多个搜索结果命中时复用目录，同时保留所有发现来源。
- 先将目标卡与合集名、视频名、章节小标题一起交给 LLM 排序，输出已有节点 ID、
  可能覆盖的核心要求、选择理由和不确定项。程序只允许展开真实存在的节点。
- 排序判断知识点和方法的语义关联，不要求标题包含相同字面词。例如合成目标
  “范式判断与分解”应优先查看“关系数据库规范理论”，目标“多表查询”应优先
  查看“SQL 查询”。这些只是取证假设，仍需字幕确认是否包含例题及所需解法。
- 标题笼统时保留为不确定候选；允许在预算内检查相邻章节或标有习题、案例的章节。
  已选章节无字幕或只讲概念时，优先补选同课程相关章节，再回到其他候选课程。
- 合集中的其他 BV 通过“目录发现”加入同一候选队列，记录父节点和入选原因；
  与搜索命中的 BV 统一去重，字幕按 BV、CID 去重，所有读取共用任务预算。
- 目录读取失败、分页未完成或触及条目上限时，保存已读范围及未展开状态；
  不把“没有读到相关章节”解释为“整门课程没有相关内容”。

最终路径为“搜索命中的课程 → 相关章节 → 具体 BV/分 P → 字幕中的例题证据”。
同一课程多个章节可以分别支持不同要求，但不得将不同例题拼成一题，或把一个
章节的结论扩展为整门课程已核验。只有概念讲解而目标要求例题时，不能判为达标。

## 4. 证据提取与跨块综合核验

- 字幕继续按块处理，但分块阶段只提取“哪个要求获得什么支持、对应字幕编号、
  讲解上下文和限制”，不直接决定整个视频是否推荐。
- 保存全部有效分块结果，包括正向、负向、未知及处理范围；重叠字幕的重复证据
  去重，未处理内容始终标记未知。
- 新增独立综合核验步骤：读取目标卡、候选信息、各块证据及必要原文上下文，
  逐项形成最终覆盖矩阵，检查支持深度、缺失项和矛盾。
- 综合核验不能凭摘要创造新引用；需要更多上下文时，只能申请读取指定的原字幕
  范围，并计入预算。
- 同一道例题的条件、方法和结论必须具有可确认的上下文关联；不能把不同题目的
  零散步骤拼成完整解法。关联不明则降为证据不足。
- 程序验证要求 ID、字幕编号、来源 CID、引用关系和最终通过条件。引用存在
  只证明来源可回查，不冒充程序已经验证语义正确。
- 删除当前“取所有字幕块中最正向判断”的逻辑。最终展示逐项覆盖、缺失内容、
  匹配理由及真实证据时间点；不连续证据分别展示，不合成虚假讲解区间。
- 推荐排序先比较核心要求覆盖与讲解深度，再比较补充要求；未核验候选不能混入
  正式推荐。同一视频的多个分 P 合并展示，分别保留依据。

## 5. 调度、预算、停止与运行记录

### 5.1 默认预算

| 项目 | 默认边界 |
| --- | --- |
| 检索目标 | 1 个有字幕证据、满足目标要求的讲解 |
| 搜索轮数 | 最多 3 轮 |
| 每轮搜索词 | 最多 3 条，每条只取第一页 |
| 候选池 | 搜索和目录发现合计最多 180 个 BV |
| 课程目录 | 最多 3 个直接关联合集，合计最多接纳 200 个目录节点 |
| 展开视频信息 | 最多 10 个视频 |
| 尝试读取字幕 | 最多 15 个单视频或分 P 单元 |
| 核验 | 最多启动 5 个有可用字幕的单元，每 BV 最多 3 个 |
| 单分 P 字幕 | 最多 60,000 字符 |
| 平台请求 | 任务级最多 60 次 |
| LLM 请求 | 任务级最多 48 次 |
| 累计执行时间 | 最多 30 分钟 |
| 估算 token | 任务级最多 600,000 |

无字幕仍消耗读取预算，但不占完整核验名额。
普通单视频计为一个单元。精确阶段最多展开 6 个视频、尝试 10 个字幕单元、
启动 3 个单元核验，并最多使用一半平台请求、模型请求及估算 token 额度，给课程阶段保留预算。
计数包含已启动而未完成的核验；恢复同一单元不重复占用启动名额。
目录发现的 BV 同样占视频展开名额，其分 P 占字幕尝试和核验名额；目录分页也计入
平台请求额度。目录达到节点上限即停止继续分页，并展示目录未读完。
同课程候选按相关性逐个取证，不因合集较大自动获得额外名额。
推荐保留课程来源，找到一个合格讲解后不继续搜集第二个。

### 5.2 预算执行

- token 预算按请求输入估算值加输出预留额度检查，明确标注其不是实际费用保证；
  供应商返回 usage 时另行记录。每阶段设置输出上限，下一步预算不足时不发请求。
- 给正在核验的候选预留综合审核额度；不能因提取阶段耗尽额度而把未经审核的
  结果直接推荐。
- 综合预留根据当前已保存字幕、证据和下一块输出额度动态估算，不使用固定预留值。
- 格式修复最多一次，同样计入预算；连接、认证和平台风控不自动重试。

### 5.3 停止与恢复

- 停止原因明确区分：目标达成、仅有部分结果、候选耗尽、预算不足、需要澄清、
  等待搜索词确认、平台暂停、服务失败及用户取消。流程结束不等于检索成功。
- 保存队列和步骤检查点。手动重试从未完成步骤继续，继承已消耗预算；
  目标变化建立新运行，扩大预算必须重新确认。不会在重启后自动联网。
- 面板允许明确追加一次初始预算，保留已用额度；第三轮上限及每 BV 三个核验单元不变。

### 5.4 运行记录与版本

- 每一步追加保存输入引用、结构化输出、选择理由、模型和提示词版本、缓存命中、
  耗时、预算变化及错误类别。
- 凭据不进入记录，课堂材料仅留在本地，不加入公开日志或分享包。
- 保存课程目录快照、实际节点关系、分页完成状态及目录到候选的选择记录；
  恢复任务使用已确认的 BV/CID，不因目录顺序变化将旧证据绑定到另一章节。
- 对目标、证据协议和提示词统一版本化；当前旧版结果标为旧协议结果，
  不能未经重新核验直接沿用为新版“覆盖”结论。

## 6. 接口、界面与实施验收

### 6.1 接口

- 扩展现有方案接口，返回目标卡、搜索方案和预算；启动接口绑定确认后的
  目标版本、搜索词及自动调整授权。
- 增加继续任务接口，用于确认新搜索词、补充澄清和批准追加预算。
- 结果接口返回覆盖矩阵、候选队列状态、决策记录摘要及停止原因；
  进度与取消继续使用现有任务接口。

### 6.2 界面

候选和结果接口补充课程、视频、分 P 的来源路径，以及目录读取范围、章节选择理由
和各节点的未展开、待核验、无字幕、已核验状态。

前端按“目标与条件、搜索方案、运行进度、推荐与证据”组织。
展示当前正在补哪个缺失项、为何换候选及剩余额度，详细过程按需展开。
系统课程按“课程 / 视频 / 章节”展示来源，注明核验了哪些章节及未核验范围。
证据链接指向真实分 P 与字幕时间点；合集名称仅用于导航，不显示整门课程已验证。

### 6.3 实施顺序

继续在现有独立 worktree 实施，不改主目录的 PPT 功能：

1. 完成目标协议、预算和状态机。
2. 替换候选初筛与证据处理流程。
3. 接入前端目标卡、授权、进度与结果。
4. 用定向用例和人工审阅验证闭环。
5. 功能闭环确认后，再考虑恢复全量回归。

### 6.4 定向用例与验收

- 合成质量用例：标题相似但内容错误、只提及不讲解、知识点相同但方法不同、
  不同例题被误拼、跨块矛盾、首选无字幕后补选成功、改写后命中、
  重复候选和循环停止。
- 控制用例：无授权不发送新词、伪造引用、预算预留、缓存版本隔离、
  中断续跑及旧结果迁移。
- 每次入选、淘汰和停止都必须能从运行轨迹解释。
- 课程目录用例：相关例题在非首 P、目标章节在同合集另一 BV、多个搜索结果命中
  同一合集、标题相关但只有概念、标题笼统仍找到例题、首选无字幕后转下一章节、
  目录分页截断、目录顺序变化、同一 CID 重复发现及目录扩展触及总预算。
- 用合成课程目录验证：目标为“范式分解”时先选择“规范理论”章节，字幕存在
  满足目标要求的例题才推荐；只出现术语或无字幕时保留缺口，不能用课程标题补证据。
- 用例和人工审阅先验证推荐质量，再进行合成服务端到端联调；
  **在功能闭环确认之前不恢复全量回归**。
- 真实平台与真实模型验证单独进行，不将模拟通过描述为实际效果已验证。

### 6.5 当前接入限制

- 合集目录读取视频详情响应中实际提供的直接关联目录，不递归读取其他合集。
  返回条目不足总数时显示目录未读完；当前没有自动补齐目录分页的能力。
- 单 BV 最多读取前 100 个分 P 元数据；未取得的部分保持未核验。
- 早期匿名探测返回 HTTP 412；后续正式客户端的搜索和登录态字幕核查通过，记录见真实链路清单。不同视频和账号的可用性仍需分别验证。
