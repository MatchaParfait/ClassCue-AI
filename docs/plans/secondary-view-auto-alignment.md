# 副视角语音自动对齐计划

设计日期：2026-11-06。状态：首版已实现；现行行为见
[副视角自动对齐](../features/secondary-view-alignment.md)。
下文数值是首版实现默认值，可根据后续效果调整，不代表已测得的准确率或速度。

## 目标

用户在播放器的副视角设置中点击一次“自动对齐”，应用利用主视频已有字幕和副视频少量语音识别结果，估算固定时间偏移并保存。目标是粗略同步画面与讲解，不追求逐帧同步或说话人识别。

适用场景是主副视频录制同一段连续课程、两边讲解内容大致相同、时间差基本固定。若副视频剪辑过、录制中断或时钟漂移明显，不保证一个偏移能覆盖全片。

## 对齐方向

沿用现有映射：

```text
副视频时间 = 主视频时间 + 偏移
偏移 = 副视频匹配时刻 - 主视频匹配时刻
```

偏移为正表示副视频要向后播放；偏移为负表示副视频时间落后于主视频。对齐结果只修改副视角偏移，不改字幕、播放进度、主副视频文件或转写结果。已经开启“使用主视频音频”时，主音频也继续按主视频时间播放。

## 一次点击的处理流程

1. **检查前置条件。** 主视频必须有非空字幕；副视频必须有可读取的音轨，关联不能正在切换或删除。缺少主字幕时明确提示，不自动转写主视频。副视频无音轨、模型不可用或存储迁移期间则显示相应原因，不改变现有偏移。
2. **选择主视频锚点。** 从已有主字幕按时间顺序寻找适合比对的句子。优先较长、包含具体词语、较少重复的句子；短应答、纯口头语和重复句不作为首选。候选句可由相邻字幕拼成连续文本，但保留对应时间范围。
3. **从锚点位置开始搜索副视频。** 对每个主字幕锚点，按当前偏移换算副视频的预计位置；没有可信旧偏移时，以主视频时间作为初始预计位置。搜索从预计位置附近开始，优先向后扩展，不要求从副视频 0 秒或视频开场扫描。给预计位置保留少量前置余量，避免从一句话中间开始；向后扩展时按语音活动跳过静音。前一锚点附近没有匹配时，继续尝试后续主字幕锚点，避免长时间空白或时间差较大导致任务卡在开头。
4. **有界识别。** 复用当前选定且已准备好的本地 ASR 模型和设备设置，不调用外部 AI，不自动下载/切换模型，也不覆盖副视频字幕或创建正式字幕记录。最多检查 ASR 返回的前 10 条原始字幕，包含短句、重复句及噪声假字幕；过滤后不返还额度。另设音频时长、调用次数和执行时间上限，具体规则见下节。识别到可靠结果后提前停止。用户可取消，取消或失败时保留原偏移并清理临时音频。
5. **匹配而不是逐条配对。** 每段副视频识别文字分别搜索主视频全部已有字幕及合理的相邻组合，不按两边字幕编号、顺序或段数一一对应。无法对应的识别结果视为噪声候选并跳过；跳过后继续检查后续语音段。
6. **评估置信度并决定是否写入。** 只有高质量、唯一性足够的文字匹配才产生偏移候选；多个独立位置得到一致候选后取稳健中心值并自动保存。证据不足时不猜、不覆盖旧值，返回最可信候选供用户明确应用，或提示没有可靠结果。

## 搜索起点与预算

主字幕锚点由连续 1–3 条字幕组成：条目间隔不超过 2 秒，组合跨度不超过
20 秒，有效字符 12–120 个，至少有 6 种不同字符。去掉明显重复及纯口头语组合。
以最早合格组合为起点，在其后 60 秒的主字幕中选最长的合格组合；
长度相同时取较早者。后备锚点最多再选两个，继续用同一选法，
与前一个锚点相隔至少 30 秒。没有合格组合时提示“主字幕缺少可对齐的长句”。
选择锚点只决定先去哪里找音频，文字匹配仍覆盖主视频全部已有字幕。

以主锚点时间 `a`、当前偏移 `d` 计算副视频预计位置 `e = a + d`。
初始偏移为 0 时，`e = a`。按以下顺序扫描每个锚点附近的区间：

| 顺序 | 副视频搜索区间 | 目的 |
| --- | --- | --- |
| 1 | `e - 15` 至 `e + 45` 秒 | 覆盖句首余量，先向后找 |
| 2 | `e + 45` 至 `e + 180` 秒 | 当前附近没找到时继续向后 |
| 3 | `e - 180` 至 `e - 15` 秒 | 剩余预算下补查较早开始的副视频 |

区间裁剪到副视频范围，空区间跳过；按上述顺序完成一个锚点后才考虑下一个。
跨锚点重叠的区间去重，已识别音频不得重复推理或重复投票。
若所有预计区间均越界，返回“预计位置超出副视频范围”，保留手动调整入口。
这不是只扫视频开头 3 分钟：主字幕 20 分钟才开始，搜索就从该位置附近开始。
固定预算下无法承诺找到任意大的起始时间差，预算耗尽应如实返回无可靠结果。

扫描使用 16 kHz 单声道临时音频和轻量语音活动检测，按时间顺序挑选有讲话的区域。
检测优先复用已安装运行时中的本地 VAD；不因没有语音而调用 ASR 识别整段静音。
只有 VAD 判定结果不等于真实讲话，噪声仍必须通过后面的文字匹配过滤。
首版实现不得因此额外下载 VAD 权重；缺少可离线使用的检测资源时返回准备提示。

| 预算 | 首版默认值 |
| --- | --- |
| 检查的原始 ASR 字幕数 | 全任务最多 10 条，噪声、空条和重复条同样计数 |
| ASR 调用次数 | 最多 10 次，空结果或过滤失败同样计数 |
| 单次送入 ASR 的音频 | 最多 12 秒，含句首句尾各最多 0.5 秒余量 |
| 累计送入 ASR 的音频 | 最多 120 秒，重叠部分也计入计算量 |
| 累计解码并检测的音频 | 最多 600 秒，包含静音；随机定位时解码的前置帧也计入 |
| 实际运行时间 | 最多 180 秒，含模型加载，排队时间不计入 |

任一预算达到就停止扩展搜索，使用已收集证据做最后判定；达到预算不等于匹配成功。
长语音区切成最多 12 秒的窗口，必要的重叠不超过 1 秒，并计入音频预算。
保留视频绝对时间，禁止把多个非连续语音区直接拼接后当作一条连续时间线。
即使 ASR 在一次调用中返回了超过剩余额度的字幕，也只检查剩余的前几条。

现有转写接口不能保证在第 10 条字幕返回前立即停止内部推理；
因此每次只提交一个小音频窗口，处理返回后再决定是否提交下一个。
执行期限需传递到解码与 ASR 取消检查；不可只给 HTTP 等待设置超时。
若后端调用暂时无法协作取消，应终止该任务独占的 worker 后再释放队列，
避免 UI 显示取消而识别仍在后台运行。

## 噪声字幕防护

副视频音质较差，ASR 可能把噪声识别为主视频中不存在的文字。不能假设副视频每条识别都有主视频对应项，也不能为了得到偏移选择“最近的一句”。

- 先对文字做统一规范化：忽略空白、常见标点和大小写差异；保留汉字、字母及数字。
- 主副两边均允许一句话被 ASR 切成多条字幕，通过相邻最多 3 段、间隔不超过 2 秒的文本组合再比较；组合中的副字幕仍共用原始 10 条预算。
- 比较需同时考虑公共连续文字长度、相似度和双方覆盖率。只共享“然后”“这个”等常见短词、短应答、单个关键词或短子串，不构成有效匹配。
- 使用确定性的字符序列匹配，不引入语义模型。为主字幕连续 3 字片段建临时索引，先找共享片段的连续位置，再对该处相邻字幕组合做完整匹配，避免每次都对全片文字做两两比较。首版用标准库 `SequenceMatcher(autojunk=False)` 建立字符对应；设相同字符数为 `M`、副/主两边有效字符数为 `n` 和 `m`，文字分数为 `S = 2M / (n + m)`。两边均至少 12 字，`M >= 12`，`S >= 0.80`，副字幕覆盖率 `M/n >= 0.75`、主候选文本覆盖率 `M/m >= 0.75` 才能进入候选。主候选选取同一连续位置的文字范围，不能将分散在全片的匹配字符相加。长噪声字幕只对上其中短短一截，会被覆盖率门槛排除。
- 检查最佳候选与次佳候选差距。先合并主字幕重叠组合产生的同一文字位置，再比较不同位置；最佳文字分数须领先次佳至少 0.08。主视频中同一句多次出现、两个位置分数接近时视为不唯一，不拿它单独定时。不得用“更接近预计时间”替代文字唯一性。
- 计算时间点优先使用实际匹配文本的起止位置，而不是含有噪声前缀的整个 ASR 片段起点。
- 无对应文本是正常结果，不记为任务错误，不阻止其他句子建立证据。

先过滤，再按 `min(M, 60) × S × min(M/n, M/m)` 排列候选。
这使长且对应程度高的句子优先，同时限制单句长度对结果的支配。
同一副字幕最多保留一个唯一位置；相邻组合、同一长句拆分及重叠音频只算一份证据。

## 偏移确认规则

每个可靠文本匹配产生：

```text
候选偏移 = 副视频匹配文字时刻 - 主视频匹配文字时刻
```

候选还必须满足时间顺序合理：主视频中较晚的匹配，副视频中也应较晚出现。优先选择文字辨识度高、覆盖率高、非重复且候选位置唯一的匹配。

- **自动保存：** 至少两个不同 ASR 输入窗口中的独立长句互相支持，主副两边的匹配范围均不重叠，起点各自至少相隔 5 秒、前后顺序一致，且候选偏移的最大差不超过 2 秒。同一长句拆成两半不算两处。保存值取上述候选排序权重对应的加权中位数，显示到 0.1 秒；不暗示帧级精度。已发现的其他同等级唯一匹配若与该组明显冲突，则不提前自动保存，继续在剩余预算内核对；预算结束仍冲突则要求手动处理。
- **单点强匹配：** 仅有一个可信匹配时不自动覆盖已有值。展示候选偏移、匹配字幕和副视频识别句，用户点击“应用候选”确认。
- **无可靠匹配或证据冲突：** 保留原偏移，说明可能是噪声、重复话语、起始差距过大或非固定时间差。用户仍可使用现有手动偏移。
- 保存成功后提示新偏移，并提供“撤销”恢复运行前的偏移。自动结果和手动偏移使用相同存储字段，刷新后仍保留。

字词时间戳存在时，对实际对应字符的时间差取中位数，再加回临时窗口的源时间；
解码必须保留媒体原始时间基准和音轨起始延迟。
只有段级时间时，只允许两边匹配均覆盖完整语句边界的候选参与自动保存。
若裁掉噪声前缀后无法知道匹配文字实际何时开始，仅返回近似候选，不按字符数均分时长。

## 任务与界面状态

自动对齐是独立的副视角任务，不启动完整视频处理、AI 题目提取或主视频重转写；遵循现有本地 ASR 任务互斥规则，模型正被其他任务占用时排队，不并行抢占 GPU/内存。开始任务前检查视频文件身份，任务中视频或关联被移除时停止并保留原偏移。

按钮及状态应简短明确：

- 空闲：`自动对齐`
- 排队：`等待 ASR`
- 运行：显示当前阶段（寻找语音、匹配字幕、确认偏移）及取消入口
- 成功：显示已保存偏移，例如 `已对齐 +8.2 秒`，可撤销
- 单点候选：显示候选时间与匹配内容，提供明确的应用操作
- 失败/无结果：显示可理解的原因，不伪造偏移，不丢失原值

重复点击返回同一关联已有的排队或运行任务，不创建重复任务。
关闭设置或离开页面后任务在后台继续，重新进入通过任务身份恢复状态；
返回另一视频页不得显示或应用旧视频的结果。取消入口复用现有任务取消接口。
程序退出中断的扫描不自动续跑，重新点击后从新快照开始；已保存结果应能从任务记录恢复。

## 接口与保存

首版接口如下：

| 操作 | 接口与行为 |
| --- | --- |
| 开始 | `POST /api/videos/{video_id}/secondary-view/alignment`，返回 202 和 `job_id` |
| 进度及结果 | 扩展现有 `GET /api/jobs/{job_id}` 的 `alignment` 字段 |
| 重新进入页面 | 扩展现有 `GET /api/videos/{video_id}/secondary-view` 返回当前关联最新 `alignment_job_id`，从任务记录查询，不新增关联表字段 |
| 取消 | 复用 `POST /api/jobs/{job_id}/cancel` |
| 应用单点候选 | `POST /api/videos/{video_id}/secondary-view/alignment/{job_id}/apply` |
| 撤销已应用结果 | `POST /api/videos/{video_id}/secondary-view/alignment/{job_id}/undo` |

应用和撤销接口使用服务端已保存结果，客户端不提交任意候选偏移。
重复应用或重复撤销返回原状态；若之后发生其他修改，返回冲突而不覆盖。
业务结果使用 `applied`、`candidate`、`no_match`、`conflict`、`stale`；
正常结束但没有匹配仍是任务 `completed`，ASR/媒体异常才是任务 `failed`，
取消沿用现有 `interrupted`。不要让“任务完成”冒充“对齐成功”。

提交时冻结库身份、主副视频 ID 与文件身份、字幕内容指纹、原偏移、模型和设备设置。
执行前及保存前重新检查；字幕、文件、关联或偏移已变则返回 `stale`，保留当前设置。
排队期间用户切换 ASR 模型或设备时结束并提示重试，不暗中修改全局设置。
保存偏移必须在事务内再次比较副视频 ID 和原偏移，只更新 `offset_ms`；
用户在运行期间切换的主音频选项应保留。
写入偏移与记录 `applied`、旧/新偏移在同一事务内完成，避免进程退出后结果不明。
撤销只有在当前关联和偏移仍等于该任务应用结果时才生效，不覆盖后续手动调整。

运行上下文和最终结果放在现有 `processing_jobs.request_json` 的专属 `alignment`
对象中，增加受控读取映射，不新建通用任务结果系统。结果只保留计数、理由、
算法版本、旧/新偏移及最多两处证据，每处最多 120 字，便于解释候选；
完整临时转写不持久化。结果跟随任务记录保留与清理，偏移沿用关联的持久存储。

  每个任务只建一次 ASR session，按窗口串行复用，继续遵守设备资源检查。

- `classcue/secondary_alignment.py`：纯文本候选、窗口计划、预算、
  偏移证据与判定；与 ASR/数据库写入分开，便于使用合成输入检查边界。
- [存储](../../classcue/video_store.py)：增加事务内比较与更新以及结果记录，
  保留关联、音频开关和已有课程状态。
- [副视角设置](../../frontend/src/components/SecondaryViewControl.tsx)：
  使用现有弹层与按钮风格增加对齐操作、取消、候选应用和撤销。
  未保存的手动偏移不作为任务初值；有未保存编辑时提示先保存或撤销编辑。
  自动保存后走现有 `onChange` 通知播放器，保持主时间，不重置续看位置。
- 新运行模块落地时补入 `release_manifest.toml`；本计划文档不作为运行资源。


## 资源、数据与隐私边界

- 只读主视频已有字幕；只对副视频临时解码的片段运行 ASR，不保存为正式字幕或分析结果。
- 不使用网络 ASR、LLM、外部服务或课程内容遥测。
- 优先复用当前已准备模型，保持用户选择的设备设置。不同模型的初始化成本并不相同，所以“最多 10 段”限制识别量，不代表任务必然即时完成；开始或排队状态要如实展示。
- 临时音频必须在成功、失败、取消和进程清理路径中删除；不将识别文本写入普通日志。
- 新增数据库持久字段、历史任务清理或发行资源之前，先确认确有需求；首版原则上仅更新现有 `offset_ms`。

## 验收场景

使用合成媒体和合成字幕验证，不使用真实课程：

- 主字幕开场为空、后段才有内容时，锚点从首个合适字幕开始，而不是副视频开头固定时长。
- 主副开始时间差较大时，能从后续锚点继续搜索；总识别段数和解码时长仍有上限。
- 两段可信匹配给出一致偏移时自动保存；正、负偏移方向正确。
- 副视频前几段是噪声假字幕、后面有真实长句时，假字幕被忽略，真实匹配仍可成功。
- 只有短应答、常见短语、重复句、错字过多、多个位置并列或偏移相互冲突时，不自动保存。
- 单点高置信候选需显式应用；应用及撤销均保留正确的旧/新偏移。
- 已启用主视频音频时，更新偏移后主音频、字幕和画面仍沿用同一主时间轴。
- 取消、ASR 失败、副视频缺少音轨、关联被删除、任务排队和进程中断均保留旧偏移并清理临时音频。

## 首版暂不包含

- 自动转写主视频、生成或覆盖任何正式字幕。
- 从副视频全片搜索、无上限重试、声纹识别、说话人区分或语义模型判断。
- 处理逐渐漂移、变速剪辑、多个独立片段的非线性时间映射。
- 自动选模型、改 ASR 设备、后台下载权重或静默覆盖用户手动设置。
- 以单条模糊或重复匹配自动保存时间偏移。

## 实施顺序

1. 实现纯文本匹配与预算规则，用噪声插入、重复句和正负偏移合成输入检查。
2. 接入局部解码和已准备 ASR，确认没有全片预处理、隐藏下载或超预算调用。
3. 接入任务队列、结果保存与冲突检查，覆盖取消、用户改偏移和异常中断。
4. 增加设置弹层交互，并针对主音频与字幕同步做范围内检查。

只跑涉及模块的检查。假 ASR 测试用于确认流程及边界，不能代表差音质识别效果；
后续使用经授权的媒体评估效果时，再据结果调整集中定义的阈值。
