按用户确认的收尾范围，当前环境的 ASR 实机补验单列记录，不继续阻塞 MCP 接入交付。现行接口见

后续扩展：插件 `0.5.0` 在原 8 个工具上新增完整批处理的预览、启动、重试和资源恢复，
查询／取消也支持既有批处理任务。以下保留第一版原始设计；
当前 12 个课程工具的参数与行为以课程工具说明为准。

## 1. 第一版目标

提供 **8 个 MCP 工具和 1 个简短的课程学习 Skill**，让用户在 Codex 中用自然语言完成：

- 找课程内容，读取教师原话，获得课次、时间和播放链接。
- 按需打开 ClassCue，定位到对应讲解。
- 使用 ClassCue 当前默认 ASR，转写课程或选定视频。
- 查询转写进度，取消不再需要的任务。

第一版处理已导入 ClassCue 的本地视频，不包含网课下载、网页登录或下载来源管理。

## 2. 工具总表

最后一列是拟展示给 Agent 的工具说明。参数格式、返回字段和限制放在工具定义中，
不把整套实现细节塞进说明。

| 工具 | 具体用途 | 实现逻辑与主要返回内容 | 面向 Agent 的说明 |
| --- | --- | --- | --- |
| `list_courses` 列出课程 | 确认“数据库”指哪门课程 | 读取现有课程与文件夹绑定，可按名称筛选；返回课程 ID、名称、视频数、有字幕数。 | 查找 ClassCue 课程，获取课程 ID 和字幕覆盖情况。 |
| `list_videos` 列出视频 | 查看课次，找到缺字幕的视频 | 按课程查询视频，支持名称和字幕状态筛选、分页；返回视频 ID、名称、时长、字幕状态、关联转写任务 ID。 | 查看课程中的视频及字幕状态；转写前用它确认目标。 |
| `search_subtitles` 搜索字幕 | 找某个知识点出现的位置 | 复用现有字面搜索，将课程 ID 转为文件夹范围；返回命中字幕、视频名称、起止秒数、播放链接及分页信息。 | 在指定课程或全库搜索字幕关键词。支持字面匹配；结果不足时可更换关键词。 |
| `read_transcript` 读取字幕 | 核对教师原话，理解前后文 | 按视频 ID、起止秒数读取完整字幕句；限制单次返回长度，超限给出继续读取的位置；返回带时间的原文与播放链接。 | 读取视频指定时间范围的原始字幕，用于核对搜索结果和理解上下文。 |
| `open_video` 打开视频 | 替用户打开对应讲解位置 | 按视频 ID 和秒数唤起 ClassCue 复习页并定位；返回打开结果，失败明确报错。 | 用户希望观看时，打开 ClassCue 视频并定位到指定秒数。 |
| `start_transcription` 开始转写 | 转写整门课程或选定视频 | 接收课程 ID 或视频 ID 列表，使用当前默认 ASR，只处理缺字幕项；创建持久任务，立即返回任务 ID、实际模型及处理数量；相同目标的重复提交复用已有活动任务。 | 使用当前默认 ASR 为课程或指定视频生成字幕。跳过已有字幕，返回后台任务 ID。 |
| `get_job` 查询任务 | 了解转写进度和结果 | 按任务 ID 读取状态；返回进行中的视频、完成／失败／跳过数量、错误与可执行的下一步。 | 查询后台任务的进度、完成结果和失败原因。 |
| `cancel_job` 取消任务 | 停止不再需要的转写 | 按任务 ID 请求停止，保留已保存的字幕；返回“正在停止”或最终状态。 | 取消指定后台转写任务，保留已完成的字幕。 |

### 工具之间的边界

- `list_courses` 确认课程身份，`list_videos` 确认课程内容和字幕覆盖情况。
- `search_subtitles` 返回候选位置，`read_transcript` 返回核对所需的完整上下文。
- 搜索和读取结果附播放链接；只有用户希望观看时，才调用 `open_video`。
- `start_transcription` 提交任务，`get_job` 查看任务，`cancel_job` 请求停止任务。
- 第一版新增工具中的取消操作仅面向转写任务，不借此开放停止其他类型任务的能力。

不增加“自动回答问题”工具。工具返回真实资料，由 Codex 判断相关性、调整检索并整理答案。

## 3. 用户操作逻辑

### 使用前

用户正常在 ClassCue 导入视频、整理课程并设置默认 ASR，再完成一次 Codex 插件连接。
后续直接在 Codex 说需求，不必逐个指定工具。

### 场景一：查找知识点

用户说：

> 帮我找数据库课程里的规范化，老师怎么讲的？

执行流程：

1. 调用 `list_courses`，找到数据库课程；有同名课程且无法判断时，才询问用户。
2. 调用 `search_subtitles`，在该课程搜索“规范化”。
3. 结果不足时，Codex 自主尝试“范式”“函数依赖”等相关词，保持原课程范围。
4. 调用 `read_transcript`，读取候选位置附近的字幕；上下文不足时扩大时间范围。
5. 返回简短解释、少量教师原话、课次、时间和播放链接。

默认给播放链接。用户继续说“打开那段”时，再调用 `open_video`。

答案需要区分：

- **教师原话**：来自工具返回的字幕。
- **Codex 的解释**：根据上下文整理，不能冒充教师原话。
- **是否属于考点**：找到讲解只能证明讲过；声称教师明确强调考试，需要相应原话或已有考点依据。

### 场景二：批量转写

用户说：

> 把数据库课程全部用默认模型转写。

执行流程：

1. 确认课程，查看视频和字幕覆盖情况。
2. 调用一次 `start_transcription`，由 ClassCue 排队处理缺字幕的视频。
3. Codex 告知实际模型、处理数量和任务 ID，通过 `get_job` 查看进度。
4. 用户说“停止”时，调用 `cancel_job`。
5. 结束后报告完成、失败和跳过数量；有失败时说明原因和下一步。

后台任务由 ClassCue 持久管理。工具提交后立即返回，不占用一次工具调用等待整门课程转写完成。
任务状态查询只读取进度，不重新提交转写。

### 第一版的处理约定

- 使用任务启动时的默认 ASR 配置，并返回实际使用的模型。
- 跳过已有字幕，不提供覆盖式重新转写。
- 只执行 ASR，不顺带调用应用里的考点提取模型。
- 模型未就绪、媒体缺失或任务冲突时，返回明确原因，不静默更换模型。
- 搜索发现缺字幕时，说明覆盖缺口，不能把“没搜到”说成“老师没讲”。
- 搜索无结果不自动扩大到其他课程。

## 4. Harness 分工

Codex 负责对话与工具调用循环。ClassCue 提供课程数据、检索能力和后台任务；
学习 Skill 只保存必要的工作流程。

| 层 | 职责 |
| --- | --- |
| Codex | 理解问题、换搜索词、选择候选、读上下文、组织答案。 |
| 课程学习 Skill | 规定检索流程、证据要求和回答格式。 |
| ClassCue MCP／后端 | 校验范围、检索字幕、执行转写、保存任务、返回真实状态。 |

### 插件总说明

> 检索 ClassCue 本地课程字幕，读取教师讲解、定位视频，并管理使用默认 ASR 的转写任务。

### Skill 的简短规则

1. 先确认课程，使用工具返回的 ID。
2. 搜索不足时自主换词；扩大课程范围前说明。
3. 回答教师观点前读取原字幕，区分教师原话和自己的解释。
4. 附课次、时间和播放链接；缺字幕时说明覆盖情况。
5. 转写交给后台任务执行；查进度不重复提交。

工具名称、输入参数、输出字段和行为限制由各自的工具定义说明，Skill 不重复整张工具表。
ID 校验、课程范围和任务互斥由程序保证，不依赖 Agent 记住操作规矩。

## 6. 开发方向与验收重点

建议按上述 8 个工具和 1 个短 Skill 开发。暂不加入语义搜索、额外问答模型或更多管理动作。
先验证现有字面检索配合 Codex 自主换词的实际效果，再根据漏搜情况决定后续增强。

首版验收聚焦四件事：

1. **找得到**：能确认课程，换词检索，并如实说明无匹配与字幕缺失。
2. **原话准确**：回答依据实际读取的字幕，时间和视频来源可追溯。
3. **能定位**：播放链接及打开工具进入正确的视频与时间。
4. **任务可控**：批量纯转写跳过已有字幕，可查询、可停止，重复提交不重复处理。

本草案用于确认开发方向，具体参数 schema、返回结构和实现任务在方向确认后细化。
