# 高级自定义召回提示词

入口：设置 → 考点提取 → 新建或选择自定义方案 → 高级：完整提示词编辑。

## 编辑方式

高级栏默认收起。展开先显示从当前基础高、中、低召回方案派生的只读内容；点击“启用完整编辑”后可以修改系统与任务说明、判断规则、正反例和执行指令，最多 60000 字符。当前教师表达与补充偏好在启用时一起复制。

完整编辑启用后，基础选项、教师表达和补充偏好暂时禁用并保留原值；运行时不再重复追加它们。收起编辑器不关闭高级模式，仍需点击“保存方案”才生效。复制方案保留完整提示词。恢复基础编辑需要确认，恢复后使用保留的普通配置，保存前仍可撤销。

固定输出协议、当前完整请求和异常修正指令可以展开只读查看。请求预览中的实际字幕为占位，不读取用户视频，不调用 AI。编辑、组装预览和保存均不会产生模型请求。

## 固定与开放的边界

高级模式的完整业务文本是唯一业务规则来源，不附加基础召回档位的旧判断指令或正反例。基础方案仅记录派生来源，不会在后续基础提示词修改时覆盖已保存高级内容。

`prompts/exam_lab/custom_protocol.md` 固定 JSON 结构、字段类型和枚举、实际字幕编号、原文证据和输入数据边界。该协议不额外套用内置高、中、低召回的纳入标准。模型输出仍须通过原有结构校验、证据定位与引用修正；不改切块、重叠、去重或最终发布。

格式与证据引用修正指令固定。用户不能经保存接口覆盖协议字段。自定义文本即使要求增加字段或引用不存在的原文，也不能绕过后端校验。

## 存储与任务

自定义方案的原有 `config_json` 增加可选 `advanced_prompt`，不增加数据库列。没有此字段或字段为 `null` 的旧方案继续使用原有基础规则追加偏好的方式。旧任务快照不受影响。

高级方案以完整业务文本计算语义版本；改名不递增版本，修改实际提示词或切换回普通模式递增版本。普通字段在高级模式中只是恢复资料，不进入有效语义哈希。

提交任务时由后端读取已保存方案，冻结完整业务文本、固定协议及修正指令。之后修改、停用方案或更新基础模板不会改变运行、排队或恢复任务。客户端提交的伪造任务快照继续被忽略。历史考点和人工复习记录沿用原有保留与重新识别机制。

## API

- `POST /api/settings/recall-schemes/prompt-preview`：接收基础配置及可选完整业务文本，返回可编辑派生文本、固定协议、当前请求消息和修正指令；不保存、不调用模型。
- 原有方案新建和更新接口接受可选 `advanced_prompt`；非空时长度为 1–60000，空白文本拒绝。恢复普通模式传 `null`。

## 验证

后端：`tests/test_advanced_recall_prompts.py` 检查三档派生、唯一业务来源、旧数据兼容、版本、快照冻结、非法字段、格式和原文证据校验。

前端：`RecallSchemeSettings.test.tsx` 检查默认折叠、预览失败重试、完整编辑、收起保存、复制、空文本、撤销及恢复基础模式。

浏览器：`node tests/frontend_advanced_recall.cjs` 在 856、1316、1540、1920px 电脑窗口验证编辑与预览、只读协议、无溢出、保存重开和未保存提醒。所有应用请求拦截，预览使用本地真实提示词组装函数；不改真实数据库、不读取用户视频、不调用 ASR/LLM。截图和结果写入 `.runtime/advanced-recall-qa-*`。
