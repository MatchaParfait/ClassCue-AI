# 考点驱动的 B 站检索与字幕核验

## 使用与边界

复习页每个真实考点的操作区提供“B 站讲解”。补充信息仅属于当前考点，
可以填写课程及题目条件或学习需求，两项均可留空；不继承其他考点的信息。
学习需求用于限定搜索和字幕核验的目标，例如要求完整例题步骤、指定解题方法或关注某个易错点。

点击“生成搜索词”直接向当前 AI 服务发送考点、前后 20 秒课堂字幕及补充信息，生成目标卡及
精确知识点、备用课程两组搜索词，每组最多三条。目标和搜索词可以编辑；确认后才访问 B 站并将候选字幕提交给
AI 服务。生成方案不会访问 B 站，打开面板和查看历史也不会调用模型。

先执行精确知识点搜索，找到一个有字幕证据、满足核心要求及指定深度的讲解即结束。
没有合格结果时执行课程类别搜索。普通视频直接核验字幕；存在分 P 或关联合集时，
按章节标题选择取证对象。分 P 不是前提，也不会根据课程标题认定包含例题。
备用课程仍不足时可生成第三轮搜索词，默认等待用户确认，也可在启动时授权自动补搜。

每条词仅检索第一页，按 BV 去重。标题和简介只用于初筛；每次最多核验
五个单视频或分 P 单元，每个 BV 最多三个。多 P 视频最多读取前一百个分 P 的标题
供模型选择，未核验的分 P 明确显示。只读取字幕轨，不下载音视频，
不将平台摘要当作字幕。

目录读取直接关联的合集，最多三个合集、合计 200 个节点，目录发现与搜索结果共用
180 个 BV 的候选池。当前使用视频详情内提供的目录，未返回的分页内容明确显示未读完。

结果分为“覆盖目标考点”“部分相关”“不相关”“证据不足”。相关判断必须
引用本次提交的字幕编号，程序校验后由原字幕生成时间与链接。模型不能填写
时间或外部链接。字幕判断不代表看过画面，不保证是同一道题，也不修改课堂
考点原有的状态、置信度、跳转时间或考试判断。

字幕按约 12,000 字符分块，保留最多 20 秒／2,000 字符重叠；单分 P 最多
自动核验 60,000 字符。预算以完整字幕段计，不截断单句；一条异常长段可能
超过普通分块大小。未处理部分会明确标记，字幕覆盖也不等于语音或视觉完整覆盖。
空字幕、需要登录和读取失败分别保留，不根据标题生成替代推荐。

长字幕优先选择目标术语附近及均匀分布的窗口，记录实际处理范围。分块阶段只提取
证据，独立综合阶段逐项判断深度及例题连续性；程序检查证据来源、要求归属和通过条件。
部分相关结果与合格推荐分开展示，不将不同例题的步骤拼成一道题。

## 任务与数据

检索复用现有全局单任务队列，和 ASR、PPT 等任务互斥。任务类型为
`bilibili_plan`、`bilibili_search`；阶段包括 `planning`、`searching`、
`screening`、`reading`、`checking`。进度与停止沿用 `/api/jobs` 接口。
停止会在当前网络或模型请求返回后的检查点生效；平台请求最长等待 15 秒，
模型等待上限沿用连接配置，已发出的模型请求不能保证取消计费。

补充信息、输入快照、模型参数、搜索词、候选、字幕来源和核验依据保存在
当前视频库数据库，运行轨迹同时以追加记录保存。确认新方案产生新运行；继续任务保留
原运行 ID、预算及检查点。缓存按输入、模型、账号范围和证据协议隔离，有效期六小时。
默认最多 60 次平台请求、48 次模型请求、600,000 估算 token 和 30 分钟累计执行时间。
精确阶段保留一半请求和 token 额度供课程检索；估算 token 不是实际费用保证。
预算耗尽后可以明确追加一次初始预算，不重置已消耗量。平台请求不自动重试，
模型格式错误最多修复一次，修复计入预算。

原考点、任意课堂字幕或补充信息变化会使旧结果过期；更换 AI 连接参数后
需要重新生成搜索方案。考点被重新分析替换时不按标题迁移记录。视频删除
会清理其搜索记录及带课堂关联的模型缓存；第三方公开字幕缓存按期限清理。
服务重启后显示中断状态，用户手动重试，不自动恢复联网调用。

主要接口：

- `GET /api/markers/{marker_id}/bilibili`：补充信息和最近二十次记录。
- `PUT /api/markers/{marker_id}/bilibili/context`：保存考点补充信息。
- `POST /api/markers/{marker_id}/bilibili/plan`：`{"consent":true}`。
- `POST /api/markers/{marker_id}/bilibili/search`：`run_id`、`target`、精确 `queries`、备用 `course_queries`、`auto_rewrite` 和 `consent`。
- `POST /api/markers/{marker_id}/bilibili/continue`：原 `run_id` 和 `consent`；审批补搜时提交 `queries`，预算追加需显式 `increase_budget`。
- `GET/DELETE /api/bilibili/account`：读取本机登录状态或退出本机登录；不返回 Cookie。
- `POST /api/bilibili/login/start`：生成短时二维码；返回本机会话编号、二维码图像、过期时间。
- `POST /api/bilibili/login/poll`：提交 `session_id` 检查扫码状态，手机确认后自动加密保存。
- `POST /api/bilibili/login/cancel`：提交 `session_id` 取消待完成的登录。
- `POST /api/bilibili/resume`：显式 `acknowledge_account_risk` 后解除暂停。

## 凭据与平台限制

默认匿名。用户点击“扫码登录”后，用 B 站 App 扫码并在手机上确认，无需复制
Cookie 或输入账号密码。应用模拟普通网页的扫码登录流程，不使用开放平台授权，
也不保证网页接口长期稳定。

二维码在本机通过 `qrcode` 生成，不把登录地址交给第三方二维码服务。
扫码链接精确允许当前 `account.bilibili.com/h5/account-h5/auth/scan-web` 和旧版
`passport.bilibili.com/h5-app/passport/login/scan`，拒绝其他域名或路径。
二维码密钥只放在后端内存，前端只取得临时图像及随机的本机会话编号；本机会话
不超过 180 秒，每次平台轮询至少间隔 3 秒，刷新至少间隔 5 秒。关闭面板、
取消、过期或请求失败后停止轮询，需要用户手动重新发起；服务重启不恢复待登录二维码。
登录响应禁止 HTTP 缓存，二维码和会话编号不写入浏览器持久存储或数据库。

只有手机确认且响应包含有效 `SESSDATA` 才保存登录状态。优先使用响应头中的会话；
响应头缺失时兼容确认 URL 查询参数，仅解析 B 站或 Biligame 域下的 HTTPS 地址，
不访问该 URL，也不跟随跳转。只保留 `SESSDATA`、
`buvid3`，使用 Windows DPAPI 加密并原子替换本机文件；失败时保留原登录状态，
不保存刷新令牌。已有加密 Cookie 文件继续兼容，但手动 Cookie 写入接口已移除。
“退出登录”只删除 ClassCue 本机保存的会话，不主动退出手机或其他设备上的账号。
这些凭据不是平台颁发的只读令牌，不应发布或分享；不扫描浏览器，不发送给 AI，
不写入课程数据库、日志或浏览器持久存储。

网络层只允许固定 HTTPS API 和字幕资源域名，Cookie 仅发往
`api.bilibili.com`，字幕请求不携带 Cookie，不跟随重定向。登录网络层独立限制为
`passport.bilibili.com` 上的二维码生成和状态轮询两个固定路径；不携带旧登录 Cookie，
不访问登录响应中的跳转地址，也不把平台 Cookie 转发给前端。
认证错误、验证码、401/403/412/429 或已知平台风控码会在本机持久暂停，
需要用户检查后显式恢复；更换或删除凭据本身不会解除暂停。
没有 IP、账号或设备指纹轮换，没有点赞、收藏、投币或评论请求。

B 站接口不是稳定性承诺，匿名搜索和字幕可能受登录、地区或平台策略限制。
软件许可不构成平台访问或第三方内容的授权，请仅用于有权处理的学习材料。
离线模拟测试通过不能代替真实平台与所选模型的可用性验证。

## 开发整合

本功能不依赖 PPT 提取、视觉证据接口或截图数据表。和 PPT 功能整合时，
按改动逐项合并数据库初始化、API 路由和发行清单，不覆盖双方完整文件。
前端入口在复习页，不改 PPT 任务使用的单视频处理页。

自动化测试只使用临时视频库、合成字幕、模拟网络和假模型。开发预览应指定
隔离的视频库与空闲端口，不复制用户的课程数据库、登录状态或模型密钥。

实施及预算细节见 [Harness 设计](bilibili-harness-plan.md)。当前仅做定向回归与合成浏览器交互，
没有恢复全量回归。后续正式客户端已验证关键词搜索、分 P 目录及扫码后的字幕读取；
真实模型判断和浏览器时间跳转尚未验收，详见 [真实链路清单](bilibili-live-test-plan.md)。
