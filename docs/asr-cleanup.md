# ASR 权重与运行环境清理优化

实施日期：2026-10-16。

## 清理范围

设置页的垃圾桶按钮清理模型权重缓存；运行环境按钮只清理独立推理环境，保留权重。Paraformer 和 Dolphin 按当前 CPU / GPU 选择清理，另一套环境保持不变。Qwen 和 FireRed 清理各自 GPU 环境。按钮提示明确标注设备和“保留模型权重”。

页面草稿选择不会误判为已经保存的模型选择；已保存模型正在使用的环境仍保留原有禁用保护。后台模型操作锁和各设备安装锁防止清理与下载、安装、推理并发。

新增接口：

```text
DELETE /api/asr/models/{model_id}/runtime?device=cpu|gpu
```

不指定设备时，底层设备型运行环境的兼容入口仍清理该模型的两套环境。前端始终明确传入当前设备。历史 `DELETE /api/asr/models/{model_id}?remove_runtime=true` 保留原有“权重 + 全部独立环境”语义，前端环境按钮不再调用该入口。

## 性能与安全

原实现对每个后代重复 `Path.resolve()`，随后再遍历统计容量、递归遍历删除。`classcue/cleanup_progress.py` 将目录安全检查、文件数量和容量统计合并为一份清单，删除时直接消费清单。

- 先确认所有绝对目标都位于应用管理根目录，拒绝重叠目标。
- 扫描使用 `os.scandir` 和不跟随链接的文件元数据，不对每个文件反复解析整条路径。
- 所有目标完成安全检查后才开始删除；发现符号链接、Windows reparse point / junction 或特殊文件时拒绝清理。
- 删除前检查目录身份和文件链接状态；仅删除清单内的文件及目录，不新增第二次递归删除。
- 就绪标记优先删除，避免取消或文件占用后残缺环境仍被误报为可用。
- Windows 只读普通文件允许清除只读属性后重试一次；文件被占用时明确报告文件名，不无限重试。
- 停止清理会在下一次文件操作边界退出。已删除内容不回滚，剩余内容可重新清理。

五类独立环境（包括已下架 Nano 的兼容路径）和全部模型权重清理共用该实现。未完成下载清理继续限定为临时文件，也接入同样的阶段反馈。

隔离目录对比（同机、每组 3,001 文件 / 151 目录）：

| 实现 | 耗时 |
| --- | --- |
| 原检查、统计、删除流程 | 3.69 秒 |
| 单次扫描后按清单删除 | 2.21 秒 |

本次样本缩短约 40%；不保证不同磁盘、杀毒软件或文件占用条件下有相同比例。未删除用户其余模型或重建真实推理环境来做性能测试。

## 进度反馈

检查范围与释放占用 → 检查目录并统计文件 → 删除文件 → 完成。

- 检查阶段实时报告已发现的文件、目录数量，总量未知时不显示虚构百分比。
- 删除阶段显示文件数、目录数、已释放容量、当前设备与文件，以及已用时。
- 百分比按文件与目录的总条目数计算，避免文件删完但仍在删除目录时提前显示完成。
- 有至少 2 秒删除速度样本后，按近期条目处理速度估算剩余时间；扫描阶段不编造 ETA。
- 超过 8 秒没有新事件或轮询失败，撤下剩余时间并说明系统操作等待或连接状态。
- 后端最多约每 200ms 持久化一次事件；前端沿用每秒任务轮询。设置页、任务抽屉和顶部任务指示器共用数据，刷新只重新关联任务，不重复提交清理。
- 任务表增量增加可空的 `cleanup_json`，API 返回 `cleanup`。历史任务没有结构化进度时显示阶段说明，不再使用固定 5%。
