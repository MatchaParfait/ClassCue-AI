# FireRed 的提前 LLM 提取

仅在 FireRedASR2S 的完整处理任务中启用。只转写任务、已有字幕的再次分析，以及 Whisper、Qwen、Paraformer、Dolphin 均保留原流程。

## 执行方式

FireRed 沿用原生 VAD、批量识别和断点恢复。每批识别、时间戳检查与检查点保存完成后，额外通知主进程已稳定的字幕和时间轴进度。通知中的时间戳采用官方合并流程相同的毫秒截断规则；原生的最终字幕合并仍照常执行。

主进程在独立线程中使用生产环境的同一套过滤、短句合并、10 分钟切块和 30 秒重叠配置准备请求，只提前发送已经封闭的完整块。末尾尚可能扩展的块不发送；公式过滤需要后文的 20 秒上下文、短句合并的最长 30 秒范围均留有保守余量。因此“10 分钟”是字幕在原视频中的覆盖时间，并非处理的实际耗时；首个请求可能需要再等待少量后文及一个识别批次。

LLM 请求仍串行，并发数为 1；多召回模式保持原有顺序，仅第一个待分析模式与 ASR 重叠。网络调用不阻塞 ASR。

## 保留的处理规则

提前阶段只取得提取请求的原始响应，不发布字幕或考点。整段 ASR 成功后，完整字幕仍按原流程保存。分析器以最终字幕重新准备完整请求，逐块校对请求、输入时间戳、源句映射、提示词及服务配置；完全一致才复用提前的响应。

最终的 JSON 检查与修复、证据匹配与修复、跨块去重、召回结果发布，以及复习状态保留全部使用原实现。视频末尾不足 10 分钟的部分在此阶段提交。输入发生变化时，不把提前取得的旧响应套用到新输入上。

## 失败、取消和恢复

- 提前请求沿用现有超时、传输重试及响应格式降级，并保留每次真实请求的原始调用 ID、时间、用量和父调用关系。
- 提前请求耗尽重试后不在同一次任务中额外重复请求；ASR 继续完成，错误在原 AI 阶段按原规则处理。批处理仍会保存字幕并进入等待 API 恢复的状态。
- ASR 失败、资源暂停或用户停止时，不发布提前取得的考点；待处理的网络请求停止追加，已经发出的请求按现有超时返回后清理。
- 在相同配置下恢复未完成的 FireRed 任务时，可以复用未发布调用日志中的已完成响应；强制重新转写不复用上一轮未完成任务。异常退出遗留的 `prefetching` 日志同样可恢复。
- 最终实验记录在完整字幕就绪后绑定完整快照。提前请求保留前缀字幕快照哈希；最终快照与已保存字幕的绑定在一个数据库事务内完成。实验室手动预览和批准逻辑不变。

## 验证

`tests/test_early_extraction.py` 覆盖提前调用、与串行请求及结果一致、重叠去重、尾段、关键词过滤、短句合并、公式过滤、格式修复、API 错误、暂停与恢复、重复检查点通知、强制转写、其他引擎隔离及网页批处理多召回顺序。

`tests/test_firered_transcriber.py` 校验增量字幕与原生最终合并的文本、ID、时间戳、词级时间戳完全一致，包括亚毫秒截断与静音片段。
